## 2. EnvironmentProvider contract

验证 Environment execution 不由 Worker 按名称硬编码，而通过 Provider：

~~~text
Descriptor
Prepare
Activate
Inspect
Release
~~~

并验证 transport-neutral `EnvironmentRef` 可持久化、解码，并在 Worker restart 后用于 Inspect/Release。

## 3. Execution ordering

自动化和静态 contract gate 验证：

~~~text
Environment policy
  ↓
Workspace prepare
  ↓
Environment Prepare
  ↓
persist EnvironmentRef
  ↓
Environment Activate
  ↓
persist ACTIVE
  ↓
Runtime Prepare
  ↓
Runtime Start
~~~

Runtime 使用 Environment Provider 返回的 CWD / Env。Environment 在 Runtime、Verifier 与 Artifact collection 完成前保持 active，最后 Release。

## 4. Cleanup composition

Attempt cleanup 只有在以下两项均成立时才是 confirmed：

~~~text
Runtime cleanup = CONFIRMED
AND
Environment cleanup = CONFIRMED
~~~

Environment cleanup UNKNOWN 时：

- successful Runtime result 不发布为 success；
- completion 使用 `CLEANUP_UNCONFIRMED`；
- Workspace 进入既有 QUARANTINED 路径；
- Retry Safety 不获得 cleanup proof。

## 5. Restart recovery

Worker schema v5 持久：

~~~text
environment_provider
environment_ref
environment_state
environment_cleanup
~~~

restart recovery 使用 Provider Inspect/Release；UNKNOWN Environment 不静默复用，也不被当作已释放。

## 6. Capability advertisement hardening

v0.4.3 的 Environment Descriptor Registry 保留，但 Worker 广告进一步收紧为：

~~~text
registered executable Environment Provider
∩
Runtime-compatible Environment
~~~

只有 Descriptor、没有 Provider 的 Environment 不再进入 WorkerHello。

## 7. Compatibility

builtin `process` 已迁移到同一 Provider contract，现有 Codex/Claude process execution 行为保持兼容。Worker schema 从 v4 additive 升级至 v5；旧 run 的 Environment metadata 为空并继续走 legacy recovery 语义。
