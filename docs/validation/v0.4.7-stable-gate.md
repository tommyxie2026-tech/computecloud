# v0.4.7 deterministic stable release Gate

The stable Gate reads sanitized local evidence only. It does not call GitHub,
read service credentials, invoke model providers, create a release request, or
publish a release. A zero exit status means that all four real-environment
reports and the exact candidate CI evidence are internally consistent and
`release/v0.4.7.json` may be created as the next controlled step.

## Required inputs

Place these files under `dist/v0.4.7-acceptance/`:

- `runtime-report.json`: RT01–RT09 real Codex/Claude Runtime and Goal budget;
- `integration-report.json`: ENV01–ENV05 and INT01–INT04;
- `production-report.json`: VAL01–VAL12 independent-host baseline;
- `performance-report.json`: PERF01–PERF03 and RLY01–RLY05;
- `ci-evidence.json`: completed exact-candidate GitHub Actions metadata.

The first four reports must pass their dedicated validators. Their candidate
SHA must equal the Gate candidate SHA, every fixed case must be `PASSED`, all
correctness counters must be zero, and the v13→v16/restore case must pass
without a manual `user_version` change.

`ci-evidence.json` uses schema
`computecloud.v0.4.7.ci-evidence.v1` and contains only:

```json
{
  "schema_version": "computecloud.v0.4.7.ci-evidence.v1",
  "source_sha": "FULL_40_CHARACTER_SHA",
  "workflow_run_id": 123456,
  "workflow_url": "https://github.com/OWNER/computecloud/actions/runs/123456",
  "event": "push",
  "status": "completed",
  "conclusion": "success",
  "jobs": {
    "verify": "success",
    "verify-macos": "success",
    "relay-fixture": "success",
    "v047-stable-gate-contract": "success"
  },
  "relay_contracts": {
    "control_bulk_isolation": true,
    "bounded_metrics": true,
    "operations_runbook": true
  }
}
```

The abbreviated example omits the other required job names. Use
`scripts.v047_stable_gate.REQUIRED_CI_JOBS` as the authoritative fixed set and
record every one as `success`. The top-level workflow conclusion alone is not
enough. Use a completed `push` run for the exact candidate SHA so slow
production-simulation and multi-arch jobs are included. Verify the run through
the GitHub UI/API before creating the sanitized file; never copy tokens, actor
environment, logs, or arbitrary annotations into it.

## Run

```sh
make ci-v047-stable-gate V047_CANDIDATE_SHA=FULL_40_CHARACTER_SHA
```

The command writes `dist/v0.4.7-stable-gate/report.json`. A pass records the
canonical SHA-256 of every input report, the workflow run ID/URL, the CI
evidence hash, and `release_request_allowed=true`. Missing files, malformed
JSON, fixture scope, non-PASS states, candidate drift, a failed/missing CI job,
or incomplete Relay evidence write a `FAILED` report and return nonzero.

`make ci-v047-stable-gate-contract` runs the fail-closed unit contract on every
PR and main build. It does not manufacture real reports and is not a stable
release pass. Until the real inputs exist, REL-GATE remains `BLOCKED_ENV` and
`release/v0.4.7.json` remains absent.

## Candidate-to-release transition

After the Gate passes, copy its four sanitized reports and `ci-evidence.json`
to `release/evidence/v0.4.7/`, copy the Gate output byte-for-byte to
`release/evidence/v0.4.7-stable-gate.json`, and create a `release-request.v2`
request. The request records the gated candidate SHA, the committed Gate
report's file SHA-256, and its exact GitHub Actions run ID.

The `v047-release-transition` CI job validates the release PR against its base
SHA and validates the merged release commit against its direct parent. The
candidate must be that base/parent, and the transition may change only the
version plus the fixed release request, Gate report, deployment, status,
tracker, closeout, README and CHANGELOG files. The Makefile may change only its
`VERSION` assignment. Any source, script, workflow, dependency, or other build
change rejects the release transition and prevents `package` from running. CI
also revalidates the committed sanitized inputs and requires them to reproduce
the committed aggregate Gate report exactly.

```json
{
  "schema_version": "release-request.v2",
  "version": "0.4.7",
  "candidate_sha": "FULL_40_CHARACTER_SHA",
  "stable_gate": {
    "path": "release/evidence/v0.4.7-stable-gate.json",
    "sha256": "SHA256_OF_THE_COMMITTED_GATE_REPORT",
    "workflow_run_id": 123456
  }
}
```

Do not commit these evidence or request files until the real Gate returns
`PASSED`.
