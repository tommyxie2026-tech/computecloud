# 多节点 PoC 与故障验收计划

- 日期：2026-09-22
- 状态：验收计划，所有用例尚未执行；无吞吐、容量或生产可靠性实测结论
- 目标：验证 单二进制 Go computecloud + SQLite + Codex / Claude Code 的多 Agent、多模型、多节点闭环
- 关联：[主设计](../design/agent-orchestration-go.md)、[ADR-001](../adr/0001-sqlite-lightweight.md)、[契约](../contracts/agent-runtime-v1.md)

## 1. 测试布局

| 角色 | 布局与用途 |
| --- | --- |
| 控制节点 | 一个 server 进程，内置 API/调度；本地 server.db 和产物目录；不安装外部数据库或工作流引擎 |
| Worker A | 独立 Linux 主机或 VM，2 个 Agent 槽位，安装固定版本 Codex / Claude Code |
| Worker B | 第二台独立 Linux 主机或 VM，同样 2 个槽位；各节点使用独立本地 worker.db；禁止用同机两个进程替代多节点验收 |
| 数据与产物 | 受控测试 Git 仓库、固定基线 commit、可独立检查的产物存储；每 Attempt 独立写工作区 |
| 模型与身份 | 至少两种实际可用且已授权的模型配置，显式保存 engine/provider/model 解析值；共享账号额度另设低并发场景 |
| 网络 | Worker 仅主动连接控制平面；可单独阻断控制流、事件上报和整个 server 连接，不在业务生产网络做故障注入 |

两个 Worker 都需分别跑通 Codex 和 Claude 的真实只读任务，形成 2 节点 × 2 执行器的四组合证据。再同时派发 4 个独立任务，并提交第 5 个验证排队。若账号额度低于 4 并发，明确降低实际并发并把 4 并发用例记为未完成，不能伪报已通过。

模型选择使用节点支持的受信配置，不填写猜测的模型名称；记录请求模型与可获得的实际模型元数据。跨引擎的不同模型满足本期多模型目标，同一引擎多模型为可选扩展。

## 2. 先测状态，再测真实执行

先使用 Fake Adapter 定位重复交付、取消竞态、启动窗口和事件缺口等可重复故障；再在两台真实节点上运行受限 CLI。Fake Adapter 结果只证明平台行为，不证明 CLI 协议、登录和清理已验证。

真实任务至少包含：读取仓库摘要、修改独立测试文件并运行可信测试、可控长任务的取消。故障注入使用测试分支和专用身份，记录平台/CLI 二进制、Go 工具链、SQLite 驱动和内嵌数据库版本；使用容器时另记镜像摘要。

## 3. 必需用例

所有行初始状态均为“未执行”。“通过条件”是目标，不是当前系统已具备的能力。

| ID | 场景与注入点 | 通过条件 |
| --- | --- | --- |
| M01 | 两节点分别运行两执行器真实任务 | 四种组合均有目标机器、运行时版本、模型配置、原生 final 与验收结果；非 mock |
| M02 | 每节点 2 槽位，提交 5 个独立任务 | 实际同时执行不超过 4，超额任务排队；双方均参与执行，完成后可继续派发 |
| M03 | 两节点共享同一受限账号额度；与其他账号混合 | 集群总额度不超限；释放遵循停止证据；其他合格账号任务能推进 |
| M04 | A 有目标仓库缓存、B 无缓存；随后 A 无空闲槽位 | 仓库亲和是软偏好；有资格的 B 可受控准备工作区，commit 一致且无越界 |
| M05 | 指定不匹配版本、模型、节点池或能力 | 已知无效规格被拒绝；暂不可满足的任务保持 QUEUED 并说明阻塞原因；不静默降级 |
| M06 | SubmitTask 提交成功后丢弃响应，同键重发 | 只产生一个 Task；同键异参冲突 |
| M07 | 准入事务提交后、待发命令发送前 server 崩溃 | SQLite 中 Attempt 与命令同时存在；重启对账并补发，只形成一个有效执行 |
| M08 | 同一任务被多次扫描，提交取消与调度并发 | 事务与版本比较保证只分配一个活动 Attempt；只预留一次额度，取消后不能再次派发 |
| M09 | Worker 启动前后丢 ACK，并重复 StartAttempt | 持久日志和环境核查防止重复进程；不明窗口进入 RECONCILING |
| M10 | 取消与启动命令乱序，stop 先到 | Worker 持久停止墓碑，晚到 start 不得复活已取消 Attempt |
| M11 | 大量事件、慢订阅者、ReportEvents ACK 丢失 | 控制流保持可用；已确认事件无缺失；按序补传、唯一键去重、最终水位一致 |
| M12 | 控制流短暂断开后重连 | 在有效租约和身份内对账同一执行；不重新启动进程；旧 connection_epoch 被拒绝 |
| M13 | Worker 断网超过租约；随后旧节点恢复 | Task 进入核查；监督器按规则停止；没有停止证据前不重新分配写执行；旧代次不能覆盖状态 |
| M14 | Worker 进程崩溃但 CLI 进程/执行环境仍在 | 新 Worker 先检查环境和日志，再续接或停止；不能因新 worker_epoch 就创建第二份 CLI |
| M15 | 运行中取消，CLI 产生子进程；与正常完成并发 | 只出现一个合法终态；CANCELED 前具有整个执行环境清理证据；未确认则保持 CANCELING |
| M16 | server 重启、数据库未 checkpoint 时进程崩溃、较长停机 | 已提交状态与待发命令可恢复；没有重复 Agent；停机期间 Worker 仍遵守租约，不能绕过期限 |
| M17 | 同一 Session 同时提交两个后续任务 | 同一原生会话最多一个活动写持有者；非持有任务等待；失联时不能靠租约到期直接抢占 |
| M18 | 本地 Session 恢复；原节点不可用时尝试他节点 | 同节点恢复有历史和文件状态证据；缺少 portable_session 时跨节点被阻止并给出明确原因 |
| M19 | 同仓库并发写两个任务，并由另一执行器评审冻结产物 | 工作区互不覆盖；评审读取指定产物和基线；不把前一个引擎的私有会话格式当作交接协议 |
| M20 | exit 0 但缺 final、事件缺口、测试失败或主要产物缺失 | 不能标为 SUCCEEDED；保留对应错误和证据 |
| M21 | Worker 回报重复/乱序、Task 成功后晚到旧代次结果 | 按身份和版本处理，终态不回滚；晚到结果可追溯 |
| M22 | 本地 WAL 满、事件存储失败、SQLite I/O 错误 | 不假 ACK；停止接纳或受控停止；不能报告持久接受/完整成功而实际丢数据 |
| M23 | 未授权项目/凭据、过期命令、相同 key 不同参数 | 拒绝并审计；普通输入不改变权限；日志无原始凭据 |

SQLite 与轻量化附加门槛：

| ID | 场景与注入点 | 通过条件 |
| --- | --- | --- |
| S01 | 在干净节点安装平台 | 一个 Go 二进制即可提供平台服务；不依赖外部数据库/队列/工作流服务；CLI 和任务工具依赖单独列明 |
| S02 | 数据目录启动第二个 server 或第二个 worker | 同目录单实例锁生效，拒绝重复管理；不同 Worker 使用各自本地目录 |
| S03 | 人为持有数据库锁、触发 SQLITE_BUSY | 有界等待/失败；不假 ACK、不无限阻塞；幂等重试可恢复 |
| S04 | 大量日志和慢订阅、反复 checkpoint | 读事务及时结束；取消和续租仍有服务机会；DB/WAL 增长可观察，清理后无不可解释积压 |
| S05 | 按维护流程备份并在隔离目录恢复 | 数据完整性与主要产物校验通过；记录恢复点；未决执行先对账，不因旧备份重派 |
| S06 | schema 升级在事务中失败 | 服务不以半迁移状态接纳任务；能恢复原版本备份，版本标识准确 |
| S07 | 运行时与配置核查 | sqlite_version 与固定驱动一致，包含所需 WAL 修复；PRAGMA 有效值符合 ADR，非只看配置文本 |

M07～M16 的每个关键故障窗口应重复注入，记录次数及失败次数。重复次数由 PoC 计划固定，例如先做 10 次以验证可复现性；全部通过仅是验收证据，不是生产故障概率估计。

## 4. 后续能力门槛

| 能力 | 必须额外通过的测试 |
| --- | --- |
| queued_input / steer_current | 输入语义不互换；旧 turn 拒绝；原生接受状态未知时不盲目重复注入 |
| approval_response / user_input | 请求身份与摘要一致；拒绝后目标动作未执行；超时及取消使请求失效 |
| portable_session | 固定版本历史、工作区、凭据授权、工具链及路径映射完整；原节点隔离后恢复仍正确 |
| 控制平面高可用 | 首版不实现；需新的存储/恢复 ADR 后再制定测试，不通过共享 SQLite 文件模拟多副本 |

P0 批模式的审批拒绝按 PERMISSION_BLOCKED 处理，不以“界面上出现审批按钮”宣称原地审批已实现。尚未支持的可选能力必须显式返回能力错误。

## 5. 轻量运行观测

使用相同 Worker 和任务观察 server、worker 的空闲/负载资源，以及 SQLite 写等待和文件增长。平台资源与 Codex/Claude、编译测试子进程资源分别记录；不把模型响应耗时归因于 SQLite 或调度。

| 指标 | 定义/记录方法 |
| --- | --- |
| 排队时间 | Task 持久接受到准入事务提交；按阻塞原因拆分 |
| 派发时间 | 准入事务提交到 Worker 持久接收，再到 attempt.started；跨机器测量需记录时钟偏差 |
| 事件延迟 | Worker WAL 持久化到平台提交，再到订阅方可见 |
| 取消收敛时间 | CancelTask 持久接受到全部执行环境停止证明 |
| 故障恢复时间 | 注入故障到对账完成；分别记录核查原执行、受控停止和创建新 Attempt |
| 资源开销 | 各组件空闲与相同任务负载下 CPU、RSS、磁盘、连接数 |
| 运维成本 | 安装组件、备份/恢复步骤、SQLite 迁移、人工核查操作和维护量 |
| 正确性计数 | 重复执行、额度超限、已确认事件丢失、终态错误、孤儿进程、未授权恢复 |

正确性计数的验收目标均为 0。性能报告记录样本数、P50/P95、失败及预算消耗；样本不足时只给原始结果，不预设“每节点能跑多少 Agent”的结论。

## 6. 证据模板

每次验收将以下记录归档到可追溯的测试结果位置；不要填写密钥或未脱敏的用户代码。

```yaml
run_id: poc-example
status: not_run
source_commit: to_be_filled
storage:
  type: sqlite
  driver_version: to_be_filled
  sqlite_version: to_be_filled
environment_manifest_ref: to_be_filled
cases:
  - id: M13
    status: not_run
    repetitions: 0
    failures: 0
    task_ids: []
    attempt_ids: []
    injected_fault: to_be_filled
    event_watermarks_ref: to_be_filled
    process_cleanup_evidence_ref: to_be_filled
    artifact_hashes_ref: to_be_filled
    observed_result: to_be_filled
    deviations: []
```

只有必需用例通过、偏差处理完成并保存证据后，才把对应阶段标为已验证；SQLite 路线已选定，验收验证的是实现和部署是否满足设计。记录“未执行 / 不适用 / 失败”时说明原因，不能把第三方仓库的作者验收结果计作 computecloud 的通过记录。
