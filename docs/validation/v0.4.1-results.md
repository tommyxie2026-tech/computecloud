## 2. runtime-execution-flow 覆盖

### 2.1 ExecutionRef

验证 provider / transport / id 的 durable 编解码；不完整引用被拒绝。本地 transport 可携带 PID/start identity，remote transport 不要求 PID。

### 2.2 Local process identity

`process.Inspect` 验证真实 process identity。正确 identity 返回 RUNNING；identity mismatch fail closed；进程结束后返回 EXITED + cleanup confirmed。

### 2.3 Remote/API-backed fixture

fixture Provider 使用 `transport=remote_api`，Start/Inspect/Stop 不依赖本地 Agent process。Worker 完整 execution path 能写入 runtime_ref、得到 successful completion，并保持 PID=0。

### 2.4 Worker restart recovery

持久 remote runtime_ref 后：

~~~text
RUNNING -> Inspect -> Stop -> EXITED/CONFIRMED
UNKNOWN -> UNKNOWN/UNKNOWN -> CLEANUP_UNCONFIRMED
~~~

UNKNOWN 不自动 resume，也不被标记 cleanup confirmed。

### 2.5 Worker schema v4

v3 -> v4 migration 保留 legacy run，并为其 runtime metadata 初始化为空；新 run 可持久 provider/transport/ref/state/cleanup。

### 2.6 Core dispatch scan

CI 静态检查：

- Worker Agent path 必须调用 `provider.Start`；
- Worker Agent path 不得保留 `process.Run(execCtx, r.Executable, ...)`；
- Worker recovery 必须调用 Provider Inspect/Stop。

Verifier 的独立 trusted local process 不属于该禁止范围。

## 3. Compatibility

当前回归 Gate 证明现有 single/MapReduce、Retry、Artifact、Workspace、Long-running、Fair Scheduling 与 Runtime v2 contract 未因 transport abstraction 失效。

Codex/Claude profile 名、Job/Task API 和 Server schema 不变；Worker schema 升级为 v4。

## 4. Safety invariants

~~~text
Provider owns Runtime execution transport
remote Runtime can complete with no local PID
runtime_ref is persisted by started callback before Worker RUNNING ownership
unknown remote cleanup fails closed
restart does not silently resume unknown remote execution
Verifier remains separately controlled
generation fencing remains authoritative
Artifact/Workspace lifecycle remains authoritative
~~~
