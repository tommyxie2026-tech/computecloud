# v0.4.7 representative cache and real NAT Relay acceptance

`PERF-01 / RLY-NET` closes only after representative repository measurements
on real Linux Workers and explicit `direct_then_relay` runs over a non-loopback
NAT topology. Local microbenchmarks and GitHub Actions fixtures remain regression
evidence and cannot satisfy this Gate.

Store the sanitized report at
`dist/v0.4.7-acceptance/performance-report.json`. It contains raw bounded timing
samples, pinned repository commits, load shape, Worker identity hashes, binary
hashes, Attempt IDs, and boolean transport observations. It contains no source
content, network address, ticket, bearer token, prompt, or Artifact payload.

## Cache cases

Use three authorized, representative repositories with distinct `small`,
`medium`, and `large` size classes. Pin each repository to a full commit. For
each case `PERF01`–`PERF03`:

1. record at least 10 cold and 10 warm Jobs under the same declared Worker slot,
   concurrency, CPU, and memory load;
2. use a unique Attempt ID for every sample;
3. record `full_job_ms`, measured from durable Job acceptance through terminal
   result, and `preparation_ms` as its included preparation component;
4. report cold/warm sample counts, P50, P95 and the warm-P50/cold-P50 ratio.

The validator recomputes the statistics from raw samples using the median and
nearest-rank P95. It rejects a reported summary that differs from those samples.
Every repository must satisfy `warm_p50 / cold_p50 <= 0.40`. This target covers
the full Job path and preparation; it does not claim model latency reduction.

## Relay cases

| ID | Required real-network observation |
| --- | --- |
| RLY01 | Direct transport succeeds and Relay is unused. |
| RLY02 | Direct failure is deliberately forced, fallback is attempted, and Relay connects. |
| RLY03 | Traffic crosses the real NAT path; control and cancel complete while Bulk traffic is active. |
| RLY04 | A network disconnect and reconnect preserve the confirmed event watermark. |
| RLY05 | Relay restarts, a fresh ticket is acquired, both Workers reconnect, and a long task completes. |

All five cases use both independently identified Workers and unique Attempt
IDs. Record Relay, Server, and Worker binary hashes. Set `real_nat=true` and
`loopback_only=false` only after checking the actual route. Correctness counters
for duplicate Attempts, lost event watermarks, and invalid Artifacts must remain
zero.

## Validation

Run:

```sh
python3 scripts/validate_v047_performance_results.py \
  dist/v0.4.7-acceptance/performance-report.json
```

The validator rejects insufficient samples, invalid or duplicate Attempt IDs,
missing load/P95 fields, summary drift, a ratio above 0.40, duplicate/missing
cases, loopback-only Relay, absent fallback, missing NAT/control/cancel proof,
missing reconnect/restart evidence, lost watermarks, or nonzero correctness
counters. Keep the tracker `BLOCKED_ENV` until the real report and restricted
underlying logs have been reviewed.
