## 2. workspace-flow 覆盖

独立 `scripts/ci_workspace_flow.py` 覆盖以下核心路径。

### 2.1 Ownership 与 generation isolation

- Workspace identity 固化 attempt / task / generation / repository_ref / base_commit / path；
- identity 字段由 SQLite trigger 禁止修改；
- 同一 Task 的 generation 1 / generation 2 使用不同 Attempt 目录；
- 已存在 Attempt Workspace 不能被另一 generation 重新绑定。

### 2.2 Spawn fence 与 restart recovery

正常顺序：

~~~text
PREPARING
  ↓
READY
  ↓
IN_USE
  ↓
Runtime / Verifier spawn
~~~

`PREPARING/READY + pid=0` 可证明尚未进入执行 spawn window；Worker restart 可安全形成 cleanup-confirmed failure。`IN_USE + pid=0` 仍视为不确定并进入 QUARANTINED，不自动 Resume、不自动 GC。

### 2.3 Retention 与 GC

自动 GC 同时要求：

~~~text
workspace.state = RETAINED
retain_until <= now
runs.completed = 1
~~~

因此 Server 尚未确认 completion 时，即使 retention 已过期，也不能删除 Workspace。

删除路径：

~~~text
RETAINED -> DELETING -> DELETED
~~~

DELETING 可在 Worker restart 后继续；DELETED 保留 metadata tombstone。

### 2.4 Legacy inventory

启动扫描只接管能与本地 `runs` 关联的旧 Workspace。已有 durable completion + cleanup confirmed 的对象进入 RETAINED；无法证明 cleanup 的对象进入 QUARANTINED；未知目录保持原状。

### 2.5 Path safety

`internal/workspace.Path` 拒绝空 ID、`.`、`..` 和任何包含父目录/子目录语义的 workspace ID；删除始终从 Worker 固定 `data_dir/workspaces` 或 `data_dir/inputs` root 解析。

### 2.6 Quota

`workspace_max_bytes` 启用后覆盖：

- prepare 后检查；
- 运行期 watcher；
- completion 前最终检查；
- quota exceed 产生 `WORKSPACE_QUOTA_EXCEEDED`；
- quota failure 不能发布 successful completion。

### 2.7 Attempt-scoped Reduce input cleanup

`inputs/<attempt-id>` 与 Workspace 使用相同 Attempt ownership。cleanup-confirmed completion 会删除输入目录；cleanup unknown / QUARANTINED 会保留；Workspace deletion reconciliation 会再次尝试清理残留输入。

## 3. Worker schema v3 guards

自动测试验证：

- Worker `PRAGMA user_version = 3`；
- PREPARING 不能直接跳到 IN_USE；
- ownership identity 不可修改；
- 合法状态链可以完成到 DELETED；
- foreign-key / integrity 回归仍由 verify 覆盖。

## 4. Safety invariants

当前自动化支持：

~~~text
one writable workspace per Attempt
workspace ownership is immutable
two Task generations never share writable state
Runtime does not spawn before IN_USE is persisted
cleanup-unknown workspace is QUARANTINED
QUARANTINED is not auto-GC eligible
GC requires retention expiry + Server completion ack
Workspace deletion is crash-recoverable
quota failure cannot become successful completion
attempt inputs are removed only with cleanup proof
~~~

并继续继承 v0.3.0–v0.3.2 的 generation fencing、Retry Safety 与 Artifact immutable provenance。

## 6. 未覆盖

本 CI 不证明：

- 真实 Codex / Claude 对超大 Workspace 的行为；
- 独立 Linux 主机上的真实磁盘满、只读挂载、I/O error；
- 24h retention 的真实墙钟演练；
- 百万文件级 Workspace 的 Size/Quota 扫描成本；
- container/VM filesystem isolation；
- Prepared/warm Workspace；
- cross-worker Workspace migration。

这些仍应由 Production Baseline #1 或后续 Environment/Scale 阶段提供证据。
