## 2. artifact-flow 覆盖

独立 `scripts/ci_artifact_flow.py` 覆盖：

### 2.1 Accepted visibility + task result reference

- 成功 Attempt 中被 completion 选中的 Artifact：STAGED -> ACCEPTED；
- 自动建立 `task_result` reference；
- 同 Attempt 未选中 Artifact：STAGED -> ORPHANED；
- gRPC ListArtifacts 只返回 ACCEPTED；
- referenced ACCEPTED Artifact 不能转成 ORPHANED。

### 2.2 Orphan GC

~~~text
ORPHANED
  + gc_after expired
  + no reference
       ↓
DELETING
       ↓
file removed
       ↓
DELETED tombstone
~~~

验证：文件删除、path 清空、deleted_at 写入；ACCEPTED 文件不受影响；重复 reconciliation 幂等。

### 2.3 Crash recovery

测试直接构造持久 `DELETING` 状态，模拟 Server 在 DB claim 后崩溃。下一次 reconciliation 能继续完成文件删除和 tombstone。

### 2.4 Reduce input provenance

Map Artifact 在 frozen manifest barrier 提交后建立：

~~~text
ref_type = reduce_input
ref_id   = <job-id>:reduce
~~~

Reduce input authorization 要求 manifest 与 explicit reference 同时成立。

### 2.5 Job result provenance

Single/Reduce 的最终 Artifact 在 Job finish 时建立：

~~~text
ref_type = job_result
ref_id   = <job-id>
~~~

### 2.6 Schema v6 guards

Migration/unit test 验证：

- reference 只能指向 ACCEPTED；
- reference 不可 UPDATE；
- referenced ACCEPTED 不能离开 ACCEPTED；
- STAGED -> DELETING 非法；
- ORPHANED -> DELETING -> DELETED 合法；
- schema 从旧版本升级到 v6。

## 3. Safety invariants

当前仓库自动化支持：

~~~text
only ACCEPTED artifacts are externally visible
only ACCEPTED artifacts can be referenced
artifact refs are immutable
referenced artifacts are not GC-eligible
failed/retried generations remain ORPHANED
Reduce input requires immutable provenance
Job final result is explicitly pinned
DELETING is restart-recoverable
DELETED preserves a tombstone
~~~

同时继续继承：

~~~text
0 stale-generation accepted writes
0 invalid artifact publication
bounded replay-safe Retry only
deadline does not reset across Retry
~~~

## 6. 未覆盖

本 CI 不能证明：

- 真实 Codex / Claude Artifact 行为；
- 独立主机与真实跨网络传输；
- 真实磁盘 I/O error / full-disk 故障；
- 24h+ orphan grace 的墙钟时间演练；
- 大规模 Artifact 数量下 reconciliation 延迟；
- shared/object storage backend。

这些不应由 fixture 结果替代。真实 Runtime/Multi-host 仍由 Production Baseline #1 跟踪；大规模 retention/GC 属于后续版本。
