## 2. Runtime contract 覆盖

### 2.1 Registry-driven dispatch

- Worker probe 通过 Registry 查找 Runtime Provider；
- Worker execute 通过 Provider 构造 Args 和 Parser；
- unknown Runtime 在 probe/execute 前 fail closed；
- Worker/Server 核心文件静态扫描不允许重新引入 `codex_exec / claude_print` profile 特例。

### 2.2 Built-in Providers

当前内置：

~~~text
codex_exec
claude_print
~~~

Provider 自己声明 Probe、Args、Parser、Capabilities 和 Gateway eligibility；旧 profile 名称保持不变。

### 2.3 Capability namespaces

新能力使用：

~~~text
runtime:*
tool:*
environment:*
~~~

并继续广告 v0.3.x legacy capability 以保持 JobSpec compatibility。自动测试覆盖 namespaced Runtime / Tool / Environment capability 和 legacy capability 的 Scheduler match。

Provider 注册时拒绝空 capability、预先带 namespace 的 capability 和同 namespace 重复 capability，避免双重前缀及声明歧义。

### 2.4 Gateway ownership

Gateway eligibility 从 `runtime_profile == codex_exec` 特例迁移到 Provider `SupportsGateway()`。

当前：

~~~text
codex_exec    true
claude_print  false
~~~

### 2.5 Extensibility

fixture Provider 可以通过 Registry 注册并参与 contract test，不需要修改 Scheduler capability matching 或 Worker profile switch。
