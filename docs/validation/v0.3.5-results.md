## 2. fair-flow 覆盖

### 2.1 Project / Job-group fairness

Scheduler 顺序：

~~~text
effective priority
    ↓
Project round-robin
    ↓
Job/group round-robin
    ↓
oldest runnable Task
~~~

自动测试验证相同 effective priority 下 Project 轮转，以及同 Project 内 group cursor 轮转。单个 Project/Job 不能永久占有每一个新释放的执行机会。

### 2.2 Priority aging

验证：

- base priority 范围保持 0..10；
- 每经过一个 `scheduler_aging_seconds` 获得 1 级 boost；
- effective priority 最大 10；
- aging 不修改持久 base priority；
- JobSpec 可选 `limits.priority` 能传播到所有 managed Task；
- 省略 priority 保持既有默认 0。

### 2.3 Hard eligibility before aging

`retry_after > now` 与 deadline 已到的 Task 不进入 runnable group。Aging 只影响顺序，不绕过 Retry backoff、deadline、Runtime/template/capability 或并发约束。

### 2.4 Queue backpressure

验证：

- global queued-task 上限；
- per-Project queued-task 上限；
- 新提交在饱和时明确返回 queue backpressure；
- 已接受请求的 idempotent replay 即使队列之后饱和仍返回原对象；
- 已接受 Job 的内部 Reduce 创建不受 external admission gate 破坏。

### 2.5 Blocker taxonomy

自动测试覆盖：

~~~text
JOB_CAPACITY_EXHAUSTED
PROJECT_CONCURRENCY_EXHAUSTED
CREDENTIAL_CONCURRENCY_EXHAUSTED
WORKER_CAPACITY_EXHAUSTED
NO_READY_WORKER
TEMPLATE_OR_CAPABILITY_MISMATCH
~~~

Worker 分类进一步区分：

- 没有健康 Worker -> `NO_READY_WORKER`；
- 有健康 Worker 但 Runtime/template/capability 不匹配 -> `TEMPLATE_OR_CAPABILITY_MISMATCH`；
- 有兼容 Worker 但 slot 已满 -> `WORKER_CAPACITY_EXHAUSTED`。

### 2.6 Bounded scheduling

单次候选 group scan 上限为 512。公平 cursor 只保存在 Server 内存中；Server restart 可以重置短期轮转顺序，但 durable Task/Attempt 状态和 correctness 不受影响。

### 2.7 No preemption

v0.3.5 只决定“下一个可用 slot 给谁”，不会为高优先级工作抢占已经拥有 lease 的 Attempt。

## 3. 回归 Gate

v0.3.5 没有放松此前可靠性内核：

~~~text
Stage / generation fencing
bounded replay-safe Retry
Artifact immutable provenance
Workspace Attempt ownership
long-running lease/deadline semantics
cleanup proof fail-closed
~~~

原 task/retry/artifact/workspace/long-run flow 均在 PR 与 main 上继续通过。

## 4. 修复记录

开发过程中 fair-flow 首次暴露 Job priority 只进入 TaskSpec、但 managed Task SQL 未持久化 `tasks.priority` 的缺陷。修复后，Job priority 同时进入 TaskSpec 和 durable queue priority。

随后补强 blocker 分类，使 `NO_READY_WORKER`、`TEMPLATE_OR_CAPABILITY_MISMATCH` 与 `WORKER_CAPACITY_EXHAUSTED` 具有互斥、可解释的判断语义，并纳入 fair-flow。

## 5. 未覆盖

fixture 自动化不能证明：

- 真实多租户持续数小时/数天的长期公平度；
- 真实 Codex/Claude 不同任务时长分布下的 starvation 上界；
- 大于 512 活跃 group 时的生产调优值；
- 真实大规模 Worker pool 下的 scheduler latency；
- CPU/Memory/GPU 资源公平；
- Workspace/Repository affinity；
- Agent-aware scoring 或 preemption。

这些分别属于 Production Baseline #1、v0.5 Agent-aware Scheduler 与 v0.7 Scale & Resilience 的后续证据。
