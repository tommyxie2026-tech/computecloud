## 2. long-run-flow 覆盖

### 2.1 no-output != hung

fixture Runtime 在开始后保持约 4 秒无输出。期间 Worker 持续 Renew。

验证：

- `last_renewed` 单调推进；
- `lease_until` 单调推进；
- 没有基于 stdout/stderr idle 自动判定失败；
- 合法 deadline extension 后 Job 可继续到成功。

### 2.2 Explicit deadline extension

覆盖：

- HTTP deadline control；
- `jobs:extend` authorization；
- operation_id 幂等 replay；
- Job deadline 单调增加；
- child Task deadline 同步；
- terminal Job extension 拒绝；
- total runtime / per-operation bound 由 config validation 与 controller 检查共同保证。

MCP `extend_job_deadline` 使用同一个 Server controller，因此不建立第二套 deadline 语义。

### 2.3 No implicit extension

未显式延长的长 fixture 在原 deadline 后停止，不能发布 ACCEPTED Artifact，也不能最终变成 SUCCEEDED。

这证明把 Worker 固定 local deadline 移除后，Server deadline + lease/stop 仍然保持硬边界。

### 2.4 Event compaction

构造超过 `max_task_events` 的 worker event：

- event payload 只保留最新窗口；
- Task `seq` 保持单调；
- `event_floor_seq` 前移；
- `event_dedup` 保留历史 worker_seq/hash；
- `after_seq < floor` 明确返回 `EVENT_CURSOR_COMPACTED`。

因此 compaction 不会伪装成连续完整事件流，也不会破坏 Worker replay hash 校验。

### 2.5 Process-group escalation

独立 process test 使用忽略 SIGTERM 的子进程，验证：

~~~text
SIGTERM
  ↓ grace expired
SIGKILL
  ↓
Cleanup = true
~~~

`Result.TermSent / KillSent / Cleanup` 可作为 Worker `attempt.stop_escalation` 的证据源。

### 2.6 Schema v7

验证：

- Server user_version = 7；
- `attempts.last_renewed`；
- `tasks.event_floor_seq`；
- `event_dedup` worker_seq 唯一性；
- v1/v3/v4/v5/v6 迁移测试继续通过。

## 4. 未覆盖

fixture 自动化不证明：

- 真实 Codex / Claude 24h+；
- 独立物理/虚拟主机上的真实长连接；
- 实际 WAN partition、NAT、TLS reconnect；
- 极端 Runtime 无输出数小时；
- 真实 SIGSTOP / kernel I/O hang；
- 百万事件规模下 SQLite 长期 retention 成本；
- HA 控制面故障。

这些不能用 CI 替代，继续由 Production Baseline #1 和后续 Scale 阶段验证。
