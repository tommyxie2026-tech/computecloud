## 2. retry-flow 覆盖

独立 `scripts/ci_retry_flow.py` 覆盖：

### 2.1 Retry once then success

~~~text
Attempt generation 1
  -> RUNTIME_FAILED
  -> cleanup confirmed
  -> replay_safe
  -> retry scheduled
  -> persisted backoff
  -> Attempt generation 2
  -> success
~~~

验证：

- generation history 为 1 -> 2；
- deadline 不变化；
- `job.task_retry_scheduled` 存在；
- 失败 generation Artifact 不成为正式结果；
- 当前 generation 只有一个 ACCEPTED Artifact。

### 2.2 Retry budget exhaustion

~~~text
max_attempts_per_task = 2
generation 1 -> RUNTIME_FAILED
generation 2 -> RUNTIME_FAILED
                ↓
              FAILED
~~~

验证只创建两代 Attempt，并产生 `job.task_retry_exhausted`。

### 2.3 Non-retryable failure

Verifier failure 不在 retry allowlist：

- Job FAILED；
- Attempt 数仍为 1；
- 不产生 retry_scheduled。

### 2.4 Explicit replay safety

`max_attempts_per_task > 1` 且 `replay_safe=false` 的 JobSpec 被拒绝。

### 2.5 Storage

流程结束验证：

- `PRAGMA integrity_check = ok`；
- Server schema = v5。

## 4. Safety invariants

当前仓库自动化支持：

~~~text
retry only for replay_safe execution
retry only after cleanup-confirmed completion
retry only for server allowlisted error
attempt generation monotonically increases
retry does not reset deadline
stale generation remains fenced
failed-generation artifact cannot become official result
non-retryable failure remains terminal
~~~

同时继承 v0.3.0：

~~~text
0 duplicate accepted executions
0 stale-generation accepted writes
0 invalid artifact publication
0 duplicated next Stage
~~~
