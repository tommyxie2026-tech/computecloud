# v0.4.7 real Runtime and Goal budget acceptance

This procedure closes `GOAL-01 / ECO-02` only when it runs against an
authorized account, the pinned `codex_http` and `claude_http` OCI images, and
the exact release candidate SHA. Fixture output and CI simulation remain useful
regression evidence but cannot pass this Gate.

The report must conform to
[`v0.4.7-runtime-results.schema.json`](v0.4.7-runtime-results.schema.json) and
pass `scripts/validate_v047_runtime_results.py`. The validator intentionally
fails closed on a non-real environment, fixture model calls, version or digest
drift, missing native finals, incomplete usage, noncontiguous events, absent
cases, failed cases, or credential-shaped fields and values.

## Pinned inputs

- exact candidate Git SHA and the identical image build source SHA;
- Codex CLI `0.160.1` and Claude Code `2.1.292`;
- immutable controller/Attempt image references by `sha256` digest;
- authenticated Unix-socket controller endpoint;
- dedicated low-budget accounts authorized for this acceptance run.

Changing a CLI version requires updating the versioned contract and rerunning
all cases. A mutable image tag is insufficient evidence.

## Fixed cases

| ID | Required real-environment observation |
| --- | --- |
| RT01 | Start creates one run, Inspect observes it, and Stop confirms the terminal cleanup path. |
| RT02 | A Server cancellation reaches the runtime and produces the expected cancelled terminal result. |
| RT03 | A bounded deadline produces the expected timed-out terminal result. |
| RT04 | A real provider error is retained as a provider-error terminal result. |
| RT05 | Native events remain contiguous from the retained first through last sequence. |
| RT06 | The resulting Artifact retains the expected Job, Task and Attempt provenance. |
| RT07 | Controller restart does not replay the Attempt and cleanup is confirmed through Docker. |
| RT08 | `claude_http` advertises `budget_claude_estimated_usd_v1`; native estimated-cost exhaustion becomes `RUNTIME_BUDGET_EXHAUSTED`. |
| RT09 | A finite-budget Goal permits one in-flight Attempt, settles complete usage before another admission, and blocks after exhaustion. |

RT01 combines Start, Inspect, and Stop so the stable contract retains the fixed
`RT01`–`RT09` range while covering every lifecycle operation.

## Collection procedure

1. Record the candidate SHA, OCI build source SHA, immutable digests, exact CLI
   versions, start time, and the authorized-account declaration before running.
2. Run each case with unique Task and Attempt IDs. Preserve the unredacted
   native final only in the access-controlled test environment.
3. In the report, retain only the SHA-256 hash and terminal classification of
   each native final. Record numeric usage and event bounds; do not copy prompts,
   model output, bearer headers, account references, tokens, or secrets.
4. Set the top-level and every case status to `PASSED` only after the recorded
   facts are checked. Do not omit or delete a failed case.
5. Store the sanitized report at
   `dist/v0.4.7-acceptance/runtime-report.json`, then run:

```sh
python3 scripts/validate_v047_runtime_results.py \
  dist/v0.4.7-acceptance/runtime-report.json
```

A zero exit status and `{"status":"PASSED",...}` output establish that the
report is structurally complete. The reviewer must still confirm that the
attached service logs and native-final hashes came from the stated run. The
repository tracker stays `BLOCKED_ENV` until that review and the validated real
report are available.

## Failure handling

Keep the failed report and logs as run evidence, correct the environment or
implementation, and create a new report for the rerun. Never rewrite fixture
evidence as a real run. If a credential-shaped field reaches the sanitized
report, rotate the affected credential when appropriate, remove the sensitive
material from the retained artifact, and rerun validation.
