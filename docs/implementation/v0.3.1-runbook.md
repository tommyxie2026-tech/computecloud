# v0.3.1 Retry Safety 运行、升级与回退

- 日期：2026-09-26
- 目标版本：0.3.1
- Server schema：v5
- Worker schema：v2（不变）
- 关联 ADR：[ADR-006](../adr/0006-retry-safety.md)
- 关联计划：[v0.3.1-plan.md](v0.3.1-plan.md)

> 本版本的 CI 使用 Runtime fixture。真实 Codex / Claude、多机和长时间生产验收仍由 Issue #1 跟踪。

## 1. 新增 JobSpec 字段

Execution 可声明：

~~~json
{
  "replay_safe": true
}
~~~

Limits：

~~~json
{
  "max_attempts_per_task": 2
}
~~~

支持范围为 1..3。

当 max attempts > 1 时，所有 Execution 都必须显式 replay-safe。

## 2. Retry 触发条件

自动 Retry 同时要求：

1. Job-managed Task；
2. completion 已确认 cleanup；
3. Execution replay_safe；
4. error code 在 Server retry allowlist；
5. 未达到 max attempts；
6. retry backoff 到期仍早于原 deadline；
7. Job 未 cancel / stop / reconcile / terminal。

当前 allowlist：

~~~text
RUNTIME_FAILED
WORKER_RESTARTED
STORAGE_UNAVAILABLE
ARTIFACT_ERROR
~~~

## 3. 明确不 Retry

包括但不限于：

~~~text
VERIFICATION_FAILED
PROTOCOL_ERROR
JOB_INPUT_ERROR
PATCH_CONFLICT
TEMPLATE_MISMATCH
AUTHENTICATION_REQUIRED
DEADLINE_EXCEEDED
CLEANUP_UNCONFIRMED
WORKER_LOST / execution uncertain
USER_CANCEL
~~~

原则：无法证明旧执行已经停止时，宁可不 Retry。

## 4. Backoff

`tasks.retry_after` 持久化 retry 可再次 dispatch 的时间。

Task 在 Retry 等待期保持：

~~~text
state = QUEUED
blocker = RETRY_BACKOFF
attempt = ''
worker = ''
current_generation = previous generation
~~~

下一次 assignment 产生 `current_generation + 1`。

deadline 沿用第一次提交时的绝对时间，不重置。

## 5. Artifact

失败 Attempt 的 STAGED Artifact 会进入 ORPHANED；下一 generation 的 Artifact 独立注册。

只有 current generation 的 ACCEPTED Artifact 可以进入 Job Result / Reduce / download。

## 6. Schema v4 -> v5

升级新增：

~~~sql
ALTER TABLE tasks ADD COLUMN retry_after INTEGER NOT NULL DEFAULT 0;
CREATE INDEX tasks_retry_queue
  ON tasks(state,retry_after,priority DESC,created);
~~~

Schema upgrade 继续要求 active Attempt 已 drain。

## 7. 回退

v0.3.0 Server 最大 schema 为 v4；v0.3.1 首次启动迁移为 v5 后，v0.3.0 二进制应拒绝直接打开数据库。

回退：

1. 停止 Server；
2. 恢复升级前 v4 backup；
3. 使用 v0.3.0 启动；
4. 不允许 v0.3.0 直接打开 v5 DB。

## 8. CI

本地：

~~~bash
make test
make race
make smoke
make ci-flow
make ci-retry-flow
make capacity-check
~~~

GitHub Actions 新增独立 `retry-flow` Job，package 必须同时依赖：

~~~text
verify
task-flow
retry-flow
~~~

retry-flow 会上传结构化报告到 `dist/ci-retry-flow/`。

## 9. 观察事件

重点：

~~~text
task.retry_scheduled
job.task_retry_scheduled
task.retry_exhausted
job.task_retry_exhausted
~~~

排障时同时检查 Task current_generation、Attempt history、retry_after、deadline 和 Artifact state。
