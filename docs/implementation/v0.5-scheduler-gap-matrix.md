# v0.5 Agent-aware Scheduler 缺口矩阵

本文按当前 main 实现核对 Scheduler 的硬过滤、readiness 软评分、决策证据和合同覆盖。结论以代码/测试为准；CI fixture 不代表目标环境效果。当前 scoring 开关 `prepared_workspace_score_enabled` 默认关闭。

## 硬过滤与资格判断

| 要求 | 权威输入与执行位置 | 自动化证据 | 状态 | 备注/缺口 |
| --- | --- | --- | --- | --- |
| 项目授权 | Worker 会话身份 `session.identity.Projects`；`fitsWithCapabilities` | `TestAPIKeyCannotEscalateProjectsOrScopes`、`TestAgentControlReadWorkerCollectionScopedAndProjected` | implemented | 项目授权在能力判断前执行；未授权候选不进入评分。 |
| Runtime、模型、凭据、仓库、策略、Verifier | `WorkerHello.runtimes[]` 的 Runtime profile 及 models/credentials/repositories/policies/verifiers；`fitsWithCapabilities` | `TestRuntimeV2NamespacedCapabilityMatching`、`TestAssignReadinessScoringCannotOverrideCapabilityFilter` | implemented | 每项都要求 Runtime 声明匹配；readiness 只能软排序，不能授权。 |
| Job 声明的通用 capability | `TaskSpec.required_capabilities` 与 `Runtime.capabilities`；`fitsWithCapabilities` | `TestRuntimeV2NamespacedCapabilityMatching`、`TestRuntimeBudgetRequiresWorkerCapability` | implemented | 只验证字符串声明相等；字符串本身没有全局 schema、语义注册表或外部真值证明。 |
| 冻结的 Job 模板兼容性 | Job frozen execution/template digest 与 Worker Runtime `template_digests`；`fitsJob` | Job execution/template 与调度集成测试 | implemented | Job 有 frozen template digest 时要求 Worker 提供相同 digest。 |
| 公网严格隔离/Gateway 要求 | Server `isolated_only` policy、任务 `environment:container` 要求和协议专用 Gateway capability；`publicExecutionRequirements`、`assign`、`fitsWithCapabilities` | `TestPublicStrictModeRejectsProcessEnvironment`、`TestPublicStrictModeRequiresAttemptGateway`、`TestPublicStrictModeFiltersNonContainerWorker` | implemented (bounded) | Job `Workspace.isolation_profile` 目前只接受 `trusted-worktree-process`，没有 Worker 侧 typed trust class。受支持的 strict 模式/能力组合不等于通用隔离证明或任意 egress policy 验证。 |
| 凭据并发上限 | 运行中 Attempt 的 `credential_ref` 计数与配置 `Credentials`；`Server.assign` | credential concurrency / assignment tests | implemented | 在候选评分前检查；由 Server 配置和持久化 Attempt 状态决定。 |
| 项目并发上限 | 运行中 Attempt 的 project 计数与 `MaxProjectTasks`；`Server.assign` | scheduler concurrency / assignment tests | implemented | 在候选评分前检查。 |
| Worker 在线、租约与容量 | Worker 最近一次 `seen`、租约时长、WorkerHello `slots`、未释放 Attempt 数；`Server.assign` | `TestAssignSkipsWorkerAtCapacity`、`TestAssignExcludesIncompatibleWorkerFromRotation` | implemented | 过期 Worker 和满载 Worker 在选择前排除；readiness `free_slots` 不作为容量权威值。 |

## 软评分、解释和隐私

| 要求 | 当前实现 | 自动化证据 | 状态 | 备注/边界 |
| --- | --- | --- | --- | --- |
| readiness 新鲜度与输入边界 | `readiness.Fresh` 校验接收/观察/测量时间、上限与列表长度；TTL 30 秒 | `TestSignal...` readiness contract gate | implemented | unknown/stale/非法输入不给 readiness 正分。 |
| `readiness-v1` 四因素 | Runtime/Environment warmth、Repository affinity、prepare P50 粗粒度成本、实时 slots/active 容量；权重 35/30/20/15 | `TestScoreWorkerUnknownAndStaleSignalsDoNotEarnReadinessCredit`、`TestScoreWorkerMonotonicReadinessAffinityCostAndCapacity` | implemented | prepare P50 是 Worker 级粗提示，不是按 Runtime/仓库分桶的性能事实。 |
| 默认关闭与兼容 | `PreparedWorkspaceScoreEnabled` bool 默认 false；启用后只改变合格候选优先级 | `TestPreparedWorkspaceScoringDefaultsOffAndCanBeExplicitlyEnabled`、`TestInvalidPreparedWorkspaceScoringConfigFailsClosed` | implemented | 关闭时保持 least-active 与既有轮换。 |
| 确定性排序与平分轮换 | 总分降序、active 数升序、Worker ID 稳定顺序；相同分/负载组使用既有 cursor | `TestChooseHighestScoredWorkerUsesScoreThenLoadAndRotatesExactTies` | implemented | tie cursor 在成功派发后更新。 |
| 资格硬过滤不可被分数覆盖 | `Server.assign` 先完成项目/能力/模板/安全/并发/租约/容量过滤，再仅给 `workerLoads` 评分 | `TestAssignReadinessScoringCannotOverrideCapabilityFilter`、`TestReadinessCannotOverrideHardFilter` | implemented | 集成回归检查不兼容 Runtime 即使有最新匹配信号也无 score、不被选中。 |
| 有界决策解释 | 最多 32 个候选、评分开关/版本、过滤原因、分项分数和所选原因持久化为 scheduler observation | `TestAssignUsesReadinessScoreOnlyWhenEnabled`、`TestFair...` | implemented | 解释只在 Attempt 创建事务中记录；字段上限防止无界膨胀。 |
| 项目数据脱敏 | `observeCandidate` 对不具项目授权的候选隐藏 Worker ID；拒绝候选不记录 affinity/prepare 信号 | `TestReadinessCannotOverrideHardFilter`、`TestAssignUsesReadinessScoreOnlyWhenEnabled` | implemented | 当前测试覆盖拒绝候选和仓库标识脱敏。 |

## Worker 硬件/信任合同覆盖

| 需求 | 当前表达 | 状态 | 后续处理 |
| --- | --- | --- | --- |
| Worker pool | 无专用 `pool_id`/pool selector 字段；任务可用 `required_capabilities` 和 Runtime capabilities 传递任意字符串 | generic capability only | 可用于显式约定的部署，但 Server 无法校验 pool 身份、生命周期或管理边界。需要受支持的 pool 语义时，先独立设计合同和管理模型。 |
| Network zone | 无 Worker 或 Runtime 的 typed network zone 字段；只能由部署自行约定通用 capability 名称 | generic capability only | 不能据此证明路由、出口或网络分区实际生效；需独立合同及目标环境负向验证。 |
| Isolation / trust class | Job `Workspace.isolation_profile` 是 typed 输入，但当前仅接受 `trusted-worktree-process`；WorkerHello/Runtime 没有独立 typed trust/isolation class。strict public 模式另由受控 container/Gateway capability requirements 限定 | partial; no typed Worker assurance | capability 命中仅代表 Worker 声明支持，不能独立证明 sandbox 运行时可信。增加 Worker 侧 typed class 前需单独规格。 |
| 最低 CPU / 内存 / 磁盘 | Job/Worker 合同没有结构化资源要求和可验证可用资源字段；slots 是并发上限，不代表硬件资源 | not represented | 不把 `cpu:...` 等任意 capability 字符串误当成 Server 已校验的资源事实。若要支持，先设计单位、采样新鲜度、reservation 和过量分配规则。 |
| Account class | Job 选择具体 `credential_ref`；Worker Runtime 声明可访问的 credentials。无 account class/配额域的独立强类型合同 | partial; credential ref only | credential authorization 与 concurrency 已有硬过滤；账户等级/供应商计划/账单等级没有通用调度合同。 |

## CI Gate 与明确缺口

现有专用自动化入口：

- `make ci-scheduler-readiness-contract`：readiness/Worker 合同与有效性回归。
- `make ci-scheduler-explainability`：Server 解释、fairness 与调度行为回归。
- `make ci-scheduler-readiness-flow`：本机二进制与 fixture Worker 的完整 flow 报告。

当前实现/CI 已覆盖确定性、硬过滤先行、信号有效性、默认关闭和解释性。尚缺的是目标环境中双 Worker 对照数据以及 pool/network/resource/trust/account-class 等更强的类型化合同；这些不能由现有 readiness 分数推断，也不在本计划中暗中扩展。

**停止规则：** 若某项缺口需要新公共 wire 字段、SQLite schema/migration、Worker 注册/管理语义或跨组件合同，先提交独立设计供审阅；不得在本矩阵或 Scheduler 评分计划中直接引入合同变更。
