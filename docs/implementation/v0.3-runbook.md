# v0.3.0 Reliability Kernel I 运行、升级与回退

- 日期：2026-09-24
- 目标版本：0.3.0
- Server schema：v4
- Worker schema：v2（不变）
- 关联实施计划：[v0.2.1 -> v0.3.0](v0.2.1-v0.3.0-plan.md)
- 长期路线：[长期路线图](long-term-roadmap.md)

> v0.3.0 当前完成的是代码与自动化验证。真实 Codex / Claude、独立双机、24h+ Job 和真实容量仍由 Production Baseline Issue #1 验收；未完成前不得把本文当作生产认证证明。

## 1. 关键变化

v0.3.0 内部可靠性模型从隐式 Job -> Task -> one Attempt 演进为 Job -> Stage -> Task -> Attempt generation N。

对外 /v1/jobs 的 single / map_reduce 接口保持兼容；自动 Retry 仍关闭。

新增不变量：
- 一个 Task 可以保留多个历史 Attempt；
- 每个 Task 最多一个 released=0 的 active Attempt；
- Task 持久化 current generation；
- stale generation 不能 renew、上报 event、上传有效 Artifact 或提交成功；
- Worker 新 epoch 只能为旧 epoch 提交 cleanup-only 的 restart failure；
- 正式结果只使用 ACCEPTED Artifact。

## 2. 升级前检查

升级前必须：
1. 备份 Server data directory；
2. 停止新 Job 接入或启用 maintenance；
3. 等待所有 active Attempt 排空；
4. 确认 SQLite 可通过 PRAGMA integrity_check；
5. 记录当前二进制版本、数据库备份和配置文件摘要。

Server migration 仍要求旧版本 active Attempt 全部 drain。存在 released=0 Attempt 时升级会被拒绝。

## 3. Schema v3 -> v4

首次启动 v0.3.0 Server 时顺序迁移：

~~~text
schema v3
  ↓
create stages
  ↓
backfill single/map/reduce Stage
  ↓
tasks.stage_id + current_generation
  ↓
rebuild attempts: UNIQUE(task,generation) + one-active partial unique index
  ↓
artifacts.generation + state
  ↓
foreign_key_check
  ↓
PRAGMA user_version=4
~~~

迁移在事务内执行；失败不应留下部分 schema。

## 4. Stage 兼容

v0.2 Job 映射规则：single -> single Stage；map_reduce -> map Stage -> reduce Stage。

v0.3.0 不开放通用 Stage DSL。外部 Job mode 仍只有 single 与 map_reduce。

## 5. Attempt 与 Fencing

Assignment generation 不再固定为 1，而是从 Task current generation 递增。

正常 live epoch 校验：attempt_id、generation、lease_token、worker_id、attempt worker epoch、task current attempt 与 task current generation 必须一致。

Worker restart 后产生新 epoch。旧 Attempt 不能续租、不能继续提交执行事件、不能上传/接受成功 Artifact、不能提交成功；只允许以 WORKER_RESTARTED + cleanup_confirmed=true 证明旧进程已清理并结束为失败。

## 6. Artifact 状态

最低生命周期：STAGED -> ACCEPTED 或 ORPHANED。

只有 ACCEPTED Artifact 可以进入 Reduce manifest、成为 Job Result、通过正式 Job/Task artifact download 路径下载。

## 7. 回退

v0.2 二进制的最大 Server schema 是 v3；v0.3.0 升级到 v4 后，旧二进制应拒绝直接打开数据库。

回退必须停止 Server，恢复升级前 v3 备份，再启动 v0.2.x。禁止让 v0.2.x 直接打开已迁移的 schema v4 数据库。

## 8. 验证命令

~~~bash
go mod verify
go vet ./...
go test ./... -count=1
go test -race ./... -count=1
make smoke
make capacity-check
make ci-flow
~~~

必须同时满足：0 duplicate accepted executions；0 stale-generation accepted writes；0 invalid artifact publication；0 duplicated next Stage。

## 9. 当前非目标

v0.3.0 不启用 automatic retry、arbitrary DAG、Runtime API v2、EnvironmentProvider、SandboxProvider、Agent-aware scoring、multi-tenant RBAC、HA、PostgreSQL / Redis / Kafka。

下一步按路线进入 v0.3.1 Retry Safety。
