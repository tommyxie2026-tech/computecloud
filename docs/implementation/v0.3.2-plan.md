# v0.3.2 Full Artifact Lifecycle 实施计划

- 日期：2026-09-26
- 目标版本：v0.3.2
- 基线：v0.3.1 Retry Safety
- Issue：[#15](https://github.com/tommyxie2026-tech/computecloud/issues/15)
- 分支：`feat/v0.3.2-artifact-lifecycle`
- ADR：[ADR-007](../adr/0007-artifact-lifecycle.md)

## 1. Goal

把 v0.3.0 的最低 Artifact generation gating 升级为完整的可靠性生命周期：

~~~text
Attempt output
    ↓
 STAGED
  ├── success/current generation -> ACCEPTED
  │                                ├── task_result ref
  │                                ├── reduce_input ref
  │                                └── job_result ref
  └── failed/unselected ----------> ORPHANED
                                       ↓
                                   grace period
                                       ↓
                                    DELETING
                                       ↓
                                    DELETED
~~~

核心是使 Artifact 的可见、被引用、可删除和崩溃恢复都有明确事务边界，而不是扩大存储产品范围。

## 2. Milestones

### A1 — Schema v6

完成 lifecycle timestamps、`gc_after`、`deleted_at`、`artifact_refs`、ACCEPTED-only ref trigger、immutable ref trigger、referenced artifact guard 与 lifecycle transition guard。

### A2 — Acceptance and provenance

Successful Attempt 将选中的 Artifact 从 STAGED 变为 ACCEPTED 并建立 `task_result`；同 Attempt 未选中 Artifact 和失败/retried generation 进入 ORPHANED；selected result 必须存在 task_result ref。

### A3 — Stage / Job references

Reduce barrier 固化 `reduce_input` refs；Reduce input authorization 同时检查 frozen manifest + explicit ref；Job finish 固化 `job_result` ref。

### A4 — Lifecycle reconciliation

实现 ORPHANED grace window、bounded GC claim、ORPHANED -> DELETING、file delete、DELETING -> DELETED tombstone、restart/retry idempotency、stale upload temp cleanup 和安全的无 metadata 文件清理。

### A5 — Visibility

gRPC Artifact list 仅 ACCEPTED；HTTP Job artifact list/download 继续只允许 ACCEPTED；Reduce input 只允许 ACCEPTED + reduce_input ref；DELETING / DELETED 永不进入正式结果。

### A6 — CI

新增独立 GitHub Actions `artifact-flow`，覆盖 accepted visibility、immutable refs、orphan GC eligibility、two-phase delete recovery、reduce input refs、job result refs、schema v6 guards。

Release package 必须依赖：

~~~text
verify
task-flow
retry-flow
artifact-flow
~~~

## 3. Release invariants

~~~text
0 non-ACCEPTED external publication
0 referenced artifact GC
0 stale-generation publication
0 mutable artifact reference
0 silent artifact-ID byte rebinding
0 deletion state loss after restart
~~~

## 4. Compatibility

外部 JobSpec 不因 v0.3.2 改版；继续保持 v0.2 Job request schema 与现有 HTTP/MCP 子集。Server DB 从 schema v5 升级到 v6。旧二进制不能安全打开 v6 数据目录，回退必须使用升级前备份。

## 5. Non-goals

Workspace lifecycle、user-configurable retention、global Job/Event/Attempt GC、shared/object storage provider、HA、任意 Artifact graph API 均不属于本版本。

## 6. Exit gate

~~~text
go mod verify
go vet ./...
go test ./... -count=1
go test -race ./... -count=1
make smoke
make capacity-check
make ci-flow
make ci-retry-flow
make ci-artifact-flow
~~~

feature branch 与合并后的 main CI 都必须通过。

## 7. Production boundary

本版本 CI 使用本地文件系统与 fixture Runtime，不替代 #1 Production Baseline 中的真实 Codex/Claude、独立 Linux Worker、跨主机网络故障、24h+ Job、真实 Runtime 容量与生产磁盘故障演练。
