# v0.4.1 Runtime Execution 运行与升级

- Worker schema：v4
- Server schema：v7（不变）
- ADR：[ADR-013](../adr/0013-runtime-execution.md)

## 1. Runtime execution metadata

Worker `runs` 新增：

~~~text
runtime_provider
runtime_transport
runtime_ref
runtime_state
runtime_cleanup
~~~

查看：

~~~sql
SELECT id,state,runtime_provider,runtime_transport,runtime_state,runtime_cleanup
FROM runs
WHERE completed=0
ORDER BY id;
~~~

不要手工修改 runtime_ref；它由 Provider 产生并作为 restart recovery 的事实依据。

## 2. 状态解释

~~~text
runtime_state: STARTING / RUNNING / EXITED / UNKNOWN
runtime_cleanup: PENDING / CONFIRMED / UNKNOWN
~~~

`UNKNOWN` 必须按未确认清理处理，不能人工把对应 Attempt 直接改成成功。

## 3. Worker restart

有 runtime_ref：

~~~text
Inspect
 ├─ RUNNING -> Stop -> CONFIRMED 才安全
 ├─ EXITED + CONFIRMED -> safe
 └─ UNKNOWN -> CLEANUP_UNCONFIRMED
~~~

没有 runtime_ref 的旧 run 继续使用 legacy process identity / Workspace pre-spawn proof。

## 4. Local CLI

`codex_exec` 和 `claude_print` transport 为 `local_cli`。PID/start identity 只是 ExecutionRef 的 local transport 字段，不是公共 Runtime API 的必要字段。

Codex Model Gateway 参数由 Codex Provider Prepare 生成；Worker 不再拼 Codex CLI model-provider 参数。

## 5. Remote/API-backed Provider

远端 Provider 应满足：

- Start 创建稳定的远端 execution ID；
- started callback 成功后才进入正常运行阶段；
- Inspect 对同一 ID 幂等；
- Stop 对重复调用安全；
- Stop/Inspect 无法证明已停止时返回 UNKNOWN；
- 不因 Worker restart 自动新建第二个远端执行。

v0.4.1 自带 fixture 只验证这些 contract，不绑定外部商业 API。

## 6. 升级

停止 Worker 后备份其 `data_dir`，再使用 v0.4.1 启动。Worker state DB 自动从 v3 升级到 v4。

检查：

~~~sql
PRAGMA user_version;
PRAGMA integrity_check;
~~~

预期 Worker `user_version=4`、integrity check 为 `ok`。

## 7. 回退

v0.4.0 binary 不应直接打开 Worker schema v4。回退时恢复升级前 Worker data_dir backup；不要手工降低 `PRAGMA user_version`。

## 8. 巡检

重点关注：

- runtime_state=UNKNOWN；
- runtime_cleanup=UNKNOWN；
- RUNNING 但 Worker 已重新启动的记录；
- Provider Inspect/Stop error；
- CLEANUP_UNCONFIRMED；
- QUARANTINED Workspace。

## 9. 边界

本版本不提供 Session resume、Approval、EnvironmentProvider、Prepared Workspace 或通用 remote Agent credential model。
