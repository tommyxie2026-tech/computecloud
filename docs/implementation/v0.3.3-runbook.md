# v0.3.3 Workspace Lifecycle 运行与升级

- 目标版本：v0.3.3
- Worker schema：v3
- Server schema：v6（不变）
- 基线：v0.3.2
- ADR：[ADR-009](../adr/0009-workspace-lifecycle.md)

## 1. 配置

~~~yaml
worker:
  workspace_retention_ms: 86400000
  workspace_max_bytes: 0
~~~

`workspace_retention_ms` 默认 24h。`workspace_max_bytes=0` 关闭 quota；大于 0 时按 Workspace 整体 regular-file size 周期检查。

## 2. 状态

~~~text
PREPARING -> READY -> IN_USE -> RETAINED -> DELETING -> DELETED
                    \-> QUARANTINED
~~~

`QUARANTINED` 表示无法证明执行进程已安全停止，默认不自动删除。

## 3. 升级 v0.3.2 -> v0.3.3

Worker data directory 是本地状态源。升级建议：停止 Worker；保存 Worker data directory 备份；部署 v0.3.3；启动 Worker；检查 schema 和 Workspace inventory。

检查：

~~~sql
PRAGMA user_version;
PRAGMA integrity_check;
PRAGMA foreign_key_check;
~~~

预期 Worker `user_version=3`、integrity ok、foreign key check empty。

Worker schema v3 只新增 metadata table/trigger；已有 Workspace 目录由启动期 inventory reconciliation 按已有 local run 安全接管。

## 4. Inventory

~~~sql
SELECT state,count(*),coalesce(sum(size_bytes),0)
FROM workspaces
GROUP BY state
ORDER BY state;

SELECT attempt,task,generation,repository_ref,base_commit,state,retain_until,cleanup_error
FROM workspaces
ORDER BY updated;
~~~

未知且没有 local run metadata 的目录不会自动删除。

## 5. Retention / GC

自动 GC 条件：

~~~text
workspace.state = RETAINED
retain_until <= now
runs.completed = 1
~~~

满足后执行 `RETAINED -> DELETING -> DELETED`。Worker restart 会继续处理 DELETING。

如果 Workspace 是 QUARANTINED，应先人工确认进程/目录状态，不要直接修改 DB 绕过状态机。

## 6. Attempt input cleanup

Map/Reduce 输入目录位于 `inputs/<attempt-id>`。它与对应 Attempt 同生命周期：cleanup confirmed 后立即尝试删除；cleanup unknown / QUARANTINED 时保留。Workspace 进入 DELETING 时会再次尝试删除该输入目录。

因此不要人工把一个 QUARANTINED Attempt 的 inputs 目录提前清空，除非已独立确认进程不存在且完成故障处置。

## 7. Quota

出现 `WORKSPACE_QUOTA_EXCEEDED` 时，检查 Workspace baseline 大小、任务产生文件和配置上限。当前 quota 是周期扫描，不是文件系统 hard quota；短时间内可能超过阈值后才被检测。

如果不需要 quota，保持 `workspace_max_bytes: 0`，避免运行期目录扫描开销。

## 8. 回退

v0.3.2 Worker 不应直接打开 schema v3 Worker DB。回退应停止 v0.3.3 Worker、保存故障现场、恢复升级前 Worker data directory、使用 v0.3.2 binary 启动。

不要手工把 `PRAGMA user_version` 从 3 改成 2。

## 9. 重点巡检

- QUARANTINED 是否持续增长；
- DELETING 是否长期不归零；
- RETAINED bytes 是否持续增长；
- workspace path 与 metadata 是否对应；
- `WORKSPACE_ERROR` / `WORKSPACE_QUOTA_EXCEEDED`；
- Worker data disk free space。

## 10. 边界

v0.3.3 不提供 warm/prepared Workspace、shared Workspace、snapshot/checkpoint、container/VM filesystem isolation 或全局历史清理。
