# v0.4.2 ToolCapability 运行与扩展

- 目标版本：v0.4.2
- ADR：[ADR-014](../adr/0014-tool-capability.md)
- Server/Worker wire：保持兼容，不新增 protobuf breaking field

## 1. ToolCapability 模型

Tool Descriptor：

~~~text
name
version
side_effect = read_only | idempotent | mutating
legacy_default
~~~

当前内建：

~~~text
artifact_inputs_v1
job_io_v1
~~~

查看 Worker 时，namespaced capability 以 `tool:<name>` 出现。

## 2. Policy

Worker policy 可增加：

~~~yaml
policies:
  batch:
    codex_sandbox: workspace-write
    allowed_tools:
      - job_io_v1
      - artifact_inputs_v1
~~~

未配置 `allowed_tools` 时只保留 legacy-default platform Tool compatibility。

非空 allowlist 会进入 TemplateDigest；修改后需要重新生成/同步 Server 的 trusted template digest。

## 3. JobSpec

Execution 可选声明：

~~~json
{
  "tools": ["job_io_v1", "artifact_inputs_v1"]
}
~~~

Server 冻结成：

~~~text
tool:artifact_inputs_v1
tool:job_io_v1
~~~

Worker 必须同时满足：

1. Tool Registry 已安装；
2. Runtime Provider 声明 compatible；
3. Policy 允许。

## 4. Failure behavior

~~~text
Tool 未注册/Runtime 不兼容
  -> CAPABILITY_UNAVAILABLE

Tool 已注册但 Policy 禁止
  -> TOOL_POLICY_DENIED
~~~

Policy gate 在 Provider Prepare/Start 前执行，因此拒绝不会启动 Agent Runtime。

## 5. Extension rule

增加一个新 ToolCapability：

1. 注册 Descriptor；
2. 声明 side_effect；
3. 对需要它的 Runtime Provider 增加 compatible Tool name；
4. 在对应 Worker policy 中 allow；
5. 通过 Tool contract tests；
6. 只有确实需要执行语义时，再单独实现 Tool invocation adapter。

不要为新增 Tool 修改 Scheduler 的名称判断逻辑。

## 6. Compatibility

旧 Job 未声明 `tools[]` 时行为保持不变。

旧 legacy capabilities 在 v0.4 compatibility window 继续广告；新能力优先使用 namespaced capability。

## 7. Rollback

v0.4.2 不引入新的 DB schema 或 breaking protobuf，因此代码回退不需要数据库降级。

如果使用了带 `tools[]` 的新 JobSpec，回退到旧 Server 前应停止新提交；旧版本 schema parser 不接受该字段。

## 8. Observability

排查顺序：

~~~text
Job Execution.tools
  ↓
Task required_capabilities
  ↓
WorkerHello tool:* advertisement
  ↓
Runtime compatible tools
  ↓
Policy allowed_tools
  ↓
Runtime Start
~~~

出现 `TEMPLATE_OR_CAPABILITY_MISMATCH` 时优先检查 Worker 是否实际广告所需 `tool:*`；出现 `TOOL_POLICY_DENIED` 时检查 Worker Policy。

## 9. Boundary

v0.4.2 只建立 Tool capability/policy foundation，不提供任意外部 Tool 执行代理，也不改变 Retry Safety、Artifact/Workspace ownership 或 Runtime execution recovery。
