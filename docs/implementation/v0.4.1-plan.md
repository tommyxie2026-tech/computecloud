# v0.4.1 Transport-neutral Runtime Execution 实施计划

- 日期：2026-09-28
- 基线：v0.4.0 Runtime API v2 Foundation
- Issue：[#27](https://github.com/tommyxie2026-tech/computecloud/issues/27)
- 分支：`feat/v0.4.1-runtime-execution`
- ADR：[ADR-013](../adr/0013-runtime-execution.md)

## 1. Goal

把 Runtime API v2 从注册/能力抽象推进到执行 transport 抽象，使 Worker 可以运行 local CLI 或 remote/API-backed Runtime，而不把 PID/process group 写成统一执行模型。

~~~text
Worker
  ↓
Provider.Prepare
  ↓
Provider.Start
  ↓ durable ExecutionRef
Provider.Inspect / Provider.Stop
~~~

## 2. Milestones

### E1 — Execution contract

- RuntimeState / CleanupState；
- ExecutionRef；
- PrepareRequest / PreparedExecution；
- StartResult / Inspection / StopResult；
- Provider Version / Transport / Prepare / Start / Inspect / Stop。

### E2 — Local CLI bridge

- Codex/Claude 通过 Provider Start 执行；
- JSONL parser 与 protocol error cancellation 保持原语义；
- Codex Gateway CLI/env mutation 移入 Provider Prepare；
- Worker runtime path 不再直接 `process.Run(runtime executable, ...)`；
- Verifier 继续独立 trusted process。

### E3 — Worker schema v4

`runs` 增加 runtime provider/transport/ref/state/cleanup durable metadata。v3 legacy run 保持可迁移。

### E4 — Restart reconciliation

runtime_ref 存在时由 Provider Inspect/Stop 恢复；RUNNING 先 Stop；UNKNOWN fail closed；不自动 resume。

### E5 — Remote fixture

增加不创建本地 Agent PID 的 remote/API-backed fixture，验证 Start、Worker completion、Inspect、Stop 和 UNKNOWN recovery。

### E6 — CI

新增独立 `runtime-execution-flow`，覆盖 transport-neutral ref、local identity inspection、remote no-PID completion、Provider recovery、Worker schema v4 和静态 core dispatch 检查。

package 必须依赖既有八个功能 Gate + runtime-execution-flow。

## 3. Release invariants

~~~text
Provider owns Runtime transport
runtime_ref persisted before RUNNING
remote fixture completes with pid=0
UNKNOWN remote execution is fail-closed
local CLI behavior remains compatible
no profile-based Runtime transport switch in Worker core
generation fencing / Retry / Artifact / Workspace invariants remain unchanged
~~~

## 4. Compatibility

- Server schema 仍为 v7；
- Worker schema v3 -> v4；
- protobuf wire contract不变；
- `codex_exec` / `claude_print` profile 不变；
- existing Task/Job API 不变；
- `runtime:local_cli` 新增为 transport capability。

## 6. Production boundary

remote fixture 只验证 execution contract，不等同于真实第三方 Agent API。真实 Codex/Claude、多机、24h+ 和生产容量仍由 Production Baseline #1 独立验收。
