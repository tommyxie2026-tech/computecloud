## 4. Goal 集成的验收边界

现有 Guard 的 transaction 只证明其自身决策持久化，不证明创建 Attempt、编译 Graph 和发布下一 revision 已作为一体恢复。
不能在 Attempt 创建前简单调用一次独立 `ReserveAttempt` 就认定预算接入完成；GI-01 须先明确跨步骤崩溃的处理规则。

`goal-execution-flow` 的目标矩阵：

1. Legacy Job 兼容与确定性单节点/依赖图成功执行，结果保留 Job/Task/Attempt/Graph provenance。
2. 重复提交 / 重复 ready-node delivery 不生成第二个 active Attempt，不重复消耗预算。
3. Server/Worker restart 后继续使用 SQLite 中的权威 revision/generation；预算与创建之间、Guard ALLOW 与新 Graph 之间的中断可恢复。
4. stale Graph Evaluation、旧 Attempt 结果、未知 Artifact provenance 被拒绝，不能改变当前状态。
5. budget exhausted、重复 evidence、loop / 无进展触发 Guard 拒绝，不隐藏重试；`NEEDS_APPROVAL` 无法由 Planner/Evaluator 绕过。
6. 独立 migration 的升级测试、race、duplicate delivery、retry/restart 必须通过；新 Gate 纳入 main CI。

## 5. 客户端 C1 与 C2 的最小闭环

- C1 使用已有 per-Job SSE 与 durable event replay；先补 collection/read model，不再造事件总线。
- 快照与事件水位、游标过期、Server restart 与备份恢复语义先冻结契约，再实现 UI 缓存与重连。
- CI 覆盖列表分页稳定性、越权读拒绝、断连续接、重复事件去重、快照重置、Artifact hash / provenance 失败提示与 capability gating。
- C1 仅只读；不存在的 Runtime 写能力不得通过前端按钮假装可用。
- C2 开放多设备交互写入前必须具备短期单写者 lease、接管审计和撤销处理。C4 仅扩展企业策略，不延后这项基础并发保护。
- PWA 产物构建与客户端 E2E 必须先接入 CI，再定义独立发布产物；Mobile 配对、Push、商店发布留在 C3 及以后。
