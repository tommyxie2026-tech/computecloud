本计划把代码实现、自动化验证、发布和真实环境验收分开跟踪。当前 v0.4.9 迭代计划见[详细执行清单](../superpowers/plans/v0.4.9-release-iteration.md)。旧版本阶段记录只用于历史追溯；当前状态以 README、P0–P2 台账和对应 release status 为准。

## v0.4.9 发布门槛

1. 没有未解决的严重正确性或安全缺陷；不为满足发布而削弱已有 Gate。
2. 精确候选 SHA 的完整必需 CI、漏洞扫描、release package 和多架构容器验证成功。
3. v0.4.8 数据升级、备份和恢复路径有自动化证据；禁止 SQLite schema 降级。
4. 发布记录只写可复核的 SHA、CI run、归档哈希与镜像 digest；不得出现真实域名、主机名、IP、个人路径、任务 ID、提示内容、用量或密钥。
5. 真实主机、真实 Provider、生产网络和代表性性能验收继续列为待验收；fixture 或 CI 通过不构成生产认证。

## 独立的目标环境验收

- **Runtime / Goal：** 固定版本 Codex/Claude Runtime 与 MCP；核对 Start/Inspect/Stop、取消、超时、错误、事件、Artifact provenance 和预算恢复。应用估算费用不等于供应商硬账单上限。
- **Container Environment：** 在目标 OCI 主机验证文件/进程/网络隔离、崩溃恢复与清理证明；宿主 CLI 不得声称提供容器隔离。
- **Trigger / Delivery：** 使用获授权的 CI 身份验证重复事件、失败回调、来源绑定和 Server 收据；不自动创建外部 PR。
- **Relay：** 保持 `direct` 默认；在真实 NAT、断网、Relay 故障/重启和长任务条件下验证后，才可重新评估生产启用策略。
- **缓存与双 Worker：** 两个独立 Worker 分别运行真实 Job；记录跨节点分配、故障/升级恢复、Artifact 完整性、冷/热缓存 P50/P95 和完整 Job 时延。
- **公网安全：** 目标入口/WAF/源站、Worker mTLS 轮换撤销、Attempt 出站拒绝和供应商侧账单限额均需独立证据。

以上验收可以在稳定发布后推进，不改变已确认的 CI 发版门槛；任何状态变更都必须由绑定候选 SHA/镜像摘要的证据支持。

## v0.5.0 边界

v0.5.0 聚焦 Agent-aware Scheduler：先执行 Runtime、权限、凭据、项目、环境、网络和 Worker Pool 硬过滤，再以默认关闭的确定性软评分优化环境就绪、Workspace/Repository affinity 和负载选择，并记录可解释的候选原因。Mobile pairing/push、Execution Usage MVP、Private Worker Pool、容量扩展和跨节点 Artifact 分别立项，不混入 v0.4.9。
