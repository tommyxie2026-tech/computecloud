# v0.4.5 后续发布计划

- 日期：2026-09-30（JST）
- 基线：v0.4.5 Prepared Workspace / Safe Control
- 当前 main：已继续合入 C2 Job Submit / bounded Manual Retry 与 UI-04a Mobile Control Foundation
- 目标：在不扩大产品边界的前提下，先稳定 v0.4.5 之后的增量，再按小版本引入 v0.4.x Relay foundation
- 产品边界：Agent-aware Distributed Job Execution Platform / Agent Job Executor

本计划不是新的产品路线，也不把 Relay、移动端或 Goal Governance 变成独立服务。Server 仍是唯一执行事实源，Worker 主动连接，SQLite 继续作为轻量持久化基础。

## 1. 发布原则

1. 先发布已经进入 `main` 的功能增量，再开始 Relay 运行时代码。
2. 每个小版本只包含一个可独立验证的能力簇；不得把 Goal 执行集成、Relay、移动端治理和生产验收混成一个发布。
3. `direct` 是 Relay 的默认路径；`direct_then_relay` 仅显式 opt-in，未完成真实双机/NAT 验证前不宣称生产就绪。
4. 不为 Relay 增加 Job/Task/Attempt SQLite 事实源，不抢占 schema version；需要 schema 时必须单独 Contract/Migration PR。
5. PR 使用快速 CI；发布候选和 `main` 使用完整 CI，耗时 Gate 只能通过 `workflow_dispatch(run_slow=true)` 手动补跑，不能删除既有门禁。
6. 每个发布必须同时具备代码、测试、CI、升级/回滚说明和明确的已知限制。

### 范围

- C2 Job Submit 的幂等和 bounded Manual Retry；
- UI-04a Secure Mobile Connection Profile、iOS/Android bundle 验证；
- 主路线图、README、Control 文档和版本记录同步；
- 不引入 Relay 运行时代码，不引入新的 SQLite schema。

### 必须验证

- submit 幂等、retry generation fencing、旧 Attempt 拒绝；
- 手机端 profile 不落敏感正文，deep link fail closed，平台 bundle 可重复构建；

- 发布产物、SHA256、升级和回滚说明。

### 退出条件

`main` 完整 CI 通过，UI-03b/UI-04a 专项 Gate 通过，发布记录和已知限制更新；真实 Codex/Claude 额度不作为 CI 依赖。

## 4. Relay 版本的统一门禁

### Contract

- 不修改 Job/Stage/Task/Attempt wire contract；
- `TransportMode=direct|relay`、`ConnectionInfo`、短期单次 `PairTicket` 只属于连接和观测层；
- 任何公共 Proto 变更先独立提交 Contract Change PR。

### Reliability

- one active Attempt per Task；
- old generation / old connection epoch 不能提交当前结果；
- duplicate control operation 必须幂等；
- Relay restart 后只能重连，不能重放业务执行意图；
- Control/Lease/Cancel 不得被 Bulk 流量阻塞。

### Security

- 外层 Relay TLS，内层 Server↔Worker TLS；
- pairing ticket 绑定 Server、Worker、Relay、协议版本、nonce 和 expiry；
- 过期、重放、错绑、降级、错误 CA/SAN 必须 fail closed；
- Relay 不持有 Job 明文、Worker Bearer Token 或执行事实。

### CI 与发布

| Gate | PR | main / RC | 真实环境 |
| --- | --- | --- | --- |
| relay-contract | 必须 | 必须 | — |
| relay-security-negative | 必须 | 必须 | — |
| relay-direct-fallback | 必须 | 必须 | 双机/NAT补充 |
| relay-restart-recovery | 必须 | 必须 | 断网/长任务补充 |
| full package / race / smoke | 快速门禁 | 完整门禁 | — |
| dual-host / NAT / 24h | 不运行 | 手动或 nightly | 发布候选必须有记录 |

## 5. 每个版本的发布流程

~~~text
冻结范围
  ↓
Contract review / schema check
  ↓
Feature PR + unit / negative / restart tests
  ↓
快速 CI（PR）
  ↓
合入 main
  ↓
完整 CI + 手动 slow gates
  ↓
RC tag / 产物 / SBOM / SHA256
  ↓
升级、回滚、验收记录
~~~

发布记录必须包含：Implemented、Tests Added、CI Gate、Schema Version、Compatibility、Known Limitations、Remaining Work、Commit SHA，以及 `DONE / PARTIAL / BLOCKED`。

## 6. 风险与决策点

- **v0.4.6 风险**：C2/UI-04a 已进入 main，但若专项 Gate 或升级回滚证据不完整，应延后稳定发布，不夹带 Relay。
- **v0.4.7 风险**：Transport seam 若侵入 Server/Worker 既有连接生命周期，应先拆公共 Contract PR，保持 direct 路径可回退。
- **v0.4.8/0.4.9 风险**：Relay 可能放大连接数、内存和重连风暴；必须先设置配额、背压和 fail-closed 上界。
- **v0.4.10 决策点**：没有真实双机/NAT/断网/长任务证据时，只保留 Experimental，不把 Relay 作为默认或生产认证能力。
- **长期边界**：移动客户端不是通用 Worker；Relay 不参与调度、租约判断、Attempt 状态或 Artifact provenance。
