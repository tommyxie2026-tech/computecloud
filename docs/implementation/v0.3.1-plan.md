# v0.3.1 Retry Safety 实施计划

- 日期：2026-09-26
- 目标版本：v0.3.1
- 基线：v0.3.0 Reliability Kernel I
- Issue：[#12](https://github.com/tommyxie2026-tech/computecloud/issues/12)
- PR：[#13](https://github.com/tommyxie2026-tech/computecloud/pull/13)
- ADR：[ADR-006](../adr/0006-retry-safety.md)

## 1. Goal

在 v0.3.0 已有的 multi-Attempt / generation fencing 基础上，加入**受限、显式、可审计的自动 Retry**。

核心目标不是提高 Retry 次数，而是证明：

> 一个失败的 Agent Task 只有在“确定已清理 + 显式可重放 + 错误属于安全重试类别 + 仍有预算和 deadline”时，才能创建下一 generation。

## 2. Scope

### R1 — Contract

- Execution 增加 `replay_safe`；
- `max_attempts_per_task` 从固定 1 扩展为 1..3；
- max attempts > 1 时必须显式 replay-safe；
- Map/Reduce 所有 Execution 都必须满足 replay-safe。

### R2 — Persistent retry state

Server schema v5：

~~~text
tasks.retry_after
~~~

Scheduler 不在 backoff 到期前 dispatch。

### R3 — Retry controller

固定 allowlist：

~~~text
RUNTIME_FAILED
WORKER_RESTARTED
STORAGE_UNAVAILABLE
ARTIFACT_ERROR
~~~

必须同时满足：

~~~text
Job-managed Task
+ replay_safe
+ cleanup_confirmed
+ retryable error
+ generation < max_attempts
+ retry_after < deadline
+ Job still accepts execution
~~~

### R4 — Observability

增加 retry scheduled / exhausted Task 与 Job event。

### R5 — CI

新增独立 `retry-flow` GitHub Actions Job：

~~~text
retry once -> generation 1 fails -> generation 2 succeeds
retry budget exhaustion
non-retryable verifier failure
replay_safe submit gate
SQLite integrity + schema v5
~~~

CI 使用 fixture，不调用真实模型。

## 3. Non-goals

- execution-uncertain 自动 Retry；
- user-defined retry taxonomy；
- Workspace resume；
- Runtime / Tool / Environment 扩展；
- arbitrary DAG；
- HA / external queue。

## 4. Release Gate

必须通过：

~~~text
go mod verify
go vet ./...
go test ./... -count=1
go test -race ./... -count=1
make smoke
make capacity-check
make ci-flow
make ci-retry-flow
~~~

并维持：

~~~text
0 duplicate accepted executions
0 stale-generation accepted writes
0 invalid artifact publication
0 retry before cleanup proof
0 retry for non replay-safe execution
0 deadline reset across retries
~~~

## 5. Production boundary

v0.3.1 的 fixture / GitHub Actions 不替代 Issue #1：

- 真实 Codex / Claude；
- 真实 MCP；
- 独立多机；
- 24h+ Job；
- 真实网络故障；
- 真实 Runtime 容量。

Production Baseline 继续独立跟踪。
