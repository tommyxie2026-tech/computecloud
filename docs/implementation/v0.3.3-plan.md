# v0.3.3 Workspace Lifecycle 实施计划

- 日期：2026-09-27
- 目标版本：v0.3.3
- 基线：v0.3.2 Full Artifact Lifecycle
- Issue：[#18](https://github.com/tommyxie2026-tech/computecloud/issues/18)
- 分支：`feat/v0.3.3-workspace-lifecycle`
- ADR：[ADR-008](../adr/0008-workspace-lifecycle.md)

## 1. Goal

把 Worker Workspace 从“Attempt 对应目录”提升为可靠性对象，使 Retry、Worker restart、cleanup、retention 和 quota 都有明确状态边界。

## 2. Milestones

### W1 — Worker schema v3

新增 `workspaces` metadata：attempt/task/generation/repository baseline/path/state/timestamps/retain_until/size/deleted_at/cleanup_error，并用 trigger 固化 ownership 与合法状态迁移。

### W2 — Attempt-owned preparation

`PREPARING -> READY -> IN_USE` 必须在 Runtime 启动前持久化；同 Task 不同 generation 使用不同目录；ownership 冲突直接拒绝。

### W3 — Completion and restart proof

cleanup confirmed 后进入 RETAINED；cleanup unknown 进入 QUARANTINED。Worker restart 利用 Workspace 状态关闭 `STARTING + pid=0` 的 pre-spawn ambiguity。

### W4 — Retention / GC

RETAINED 只有在 `retain_until` 过期且本地 run 已得到 Server completion ack 后才进入 DELETING；删除完成后写 DELETED tombstone；DELETING 可在 restart 后恢复。

### W5 — Legacy inventory

只接管能与已有 local run 对应的历史 Workspace；未知目录保持不变。已知 legacy run 根据 durable completion cleanup proof 进入 RETAINED 或 QUARANTINED。

### W6 — Quota

新增 `workspace_max_bytes`，默认 0=disabled；prepare、运行期和 completion 前检查。超限产生 `WORKSPACE_QUOTA_EXCEEDED`，不能成功发布结果。

### W7 — CI

新增独立 `workspace-flow`，覆盖 ownership、generation isolation、restart recovery、quarantine、retention gate、two-phase deletion、legacy adoption、path guard、quota guard、schema v3。

Package 依赖：

~~~text
verify
task-flow
retry-flow
artifact-flow
workspace-flow
~~~

## 3. Compatibility

公共 Job/Task Proto 不变化；Workspace lifecycle 是 Worker 本地实现语义。

Worker DB：

~~~text
schema v2 -> v3
~~~

旧 Worker binary 不能打开 v3 data directory；回退必须恢复升级前 Worker data backup。

新增可选配置：

~~~yaml
worker:
  workspace_retention_ms: 86400000
  workspace_max_bytes: 0
~~~

`workspace_retention_ms` 默认 24h；`workspace_max_bytes=0` 表示禁用 quota。

## 5. Production boundary

fixture CI 不代表真实 Codex/Claude、多主机文件系统故障、磁盘满/只读挂载、长时间 retention 或大目录 quota 扫描性能验证。Production Baseline #1 继续独立跟踪。
