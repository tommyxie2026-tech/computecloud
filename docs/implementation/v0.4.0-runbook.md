# v0.4.0 Runtime API v2 运行与扩展

- 目标版本：v0.4.0
- 数据库：无 schema 变化
- ADR：[ADR-012](../adr/0012-runtime-api-v2.md)

## 1. Runtime Provider

Worker 启动时不再硬编码 Codex/Claude profile，而是从 Runtime Registry 查找配置中的 `runtime_profile`。

Provider 负责：

~~~text
Profile
Probe
Args
Parser
Capabilities
Gateway eligibility
~~~

配置中存在未注册 profile 时，Worker probe fail closed，不连接为可调度 Worker。

## 2. Capability

新配置/Job 优先使用 namespaced capability：

~~~text
runtime:event_stream
runtime:cancel
runtime:gateway_inference_v1

tool:job_io_v1
tool:artifact_inputs_v1

environment:process
~~~

v0.4.0 Worker 仍同时广告旧名称，以兼容 v0.3.x JobSpec。

建议新代码不再创建新的无命名空间 capability。

## 3. Codex / Claude compatibility

现有：

~~~text
runtime_profile: codex_exec
runtime_profile: claude_print
~~~

保持不变。

Policy、Model、Credential、Repository、Verifier 和 Template Digest 约束也保持不变。

## 4. Gateway

Gateway 不再通过 profile 名称判断。

只有 Provider 明确 `SupportsGateway=true` 时，Worker 接受 Assignment.Gateway。

当前内置：

~~~text
codex_exec    true
claude_print  false
~~~

## 5. 新增 Runtime Provider

新增 Provider 至少需要实现：

~~~text
Profile()
Probe()
Args()
Parser()
Capabilities()
SupportsGateway()
~~~

然后注册到 Registry。

新增 Provider 不应该修改：

~~~text
internal/worker/worker.go
internal/worker/execute.go
internal/server/server.go scheduler capability matching
~~~

如果新增 Runtime 必须修改这些核心分支，应先 Review Runtime contract 是否缺少必要抽象。

## 6. 验证

~~~bash
make ci-runtime-contract-flow
~~~

结构化报告：

~~~text
dist/ci-runtime-contract/report.json
dist/ci-runtime-contract/logs/*
~~~

其中静态 Gate 会检查 Worker/Server 核心文件是否重新出现 `codex_exec / claude_print` 特例。

## 7. 回退

v0.4.0 无数据库 migration，因此可以回退到 v0.3.5 binary，但需要：

1. 确认 JobSpec 没有使用仅 v0.4.0 Worker 才广告的 namespaced-only capability；
2. 停止 v0.4.0 Worker；
3. 部署 v0.3.5；
4. 执行 smoke / task-flow / retry-flow；
5. 检查 Worker registration。

若 Job 已要求 `runtime:* / tool:* / environment:*` capability，回退前应恢复为 legacy requirement 或等待该 Job 完成。

## 8. Non-goals

本版本没有实现 API-backed Runtime、EnvironmentProvider、Prepared Workspace、Approval 或新 Tool Executor。它只建立这些能力后续接入所需要的 Runtime Provider 边界。
