# v0.4.4 EnvironmentProvider Execution 运行与扩展

- 目标版本：v0.4.4
- Worker schema：v5
- ADR：[ADR-016](../adr/0016-environment-provider-execution.md)

## 1. 当前 Provider

当前 builtin：

~~~text
process
  isolation_class = process
  filesystem_mode = workspace
  network_mode = host
~~~

process Provider 使用现有 Worker Workspace，不拥有 Runtime 子进程；Runtime cleanup 仍由 Runtime Provider 单独证明。

## 2. Execution order

~~~text
Workspace READY/IN_USE
  ↓
Environment Prepare -> durable EnvironmentRef
  ↓
Environment Activate -> ACTIVE
  ↓
Runtime Prepare/Start
  ↓
Runtime cleanup
  ↓
Environment Release
  ↓
Attempt completion
~~~

如果 Environment cleanup 不是 CONFIRMED，Attempt completion 必须是 fail-closed，Workspace 不进入正常可 GC 的 RETAINED 路径。

## 3. Worker DB

检查：

~~~sql
PRAGMA user_version;

SELECT id,environment_provider,environment_state,environment_cleanup
FROM runs
WHERE environment_provider<>'';
~~~

预期 Worker schema `user_version = 5`。

## 4. Restart recovery

Worker 对未完成 run：

1. 先按 Runtime Provider Inspect/Stop 恢复 Runtime cleanup 证据；
2. 如果存在 EnvironmentRef，再按 Environment Provider Inspect/Release；
3. 两者都 CONFIRMED 才形成 cleanup-confirmed recovery completion；
4. 任一 UNKNOWN 时使用 `CLEANUP_UNCONFIRMED`，禁止自动重放。

## 5. 新增 Environment Provider

新增 Provider 必须：

- Descriptor 与 Provider 名称一致；
- Prepare 在外部资源进入不可逆状态前持久化 Ref；
- Activate 成功后才能启动 Runtime；
- Inspect 能在 Worker restart 后仅凭 Ref 判断状态；
- Release 幂等；
- 无法证明释放时返回 CleanupUnknown；
- 通过 environment-execution-flow contract test；
- Runtime Provider 明确声明兼容该 Environment；
- Worker Policy 明确 allow 后才可执行。

只注册 Descriptor 不会进入 Worker 广告。

## 6. Upgrade / rollback

v0.4.3 Worker schema v4 升级到 v5 为 additive migration。旧 run 的 Environment metadata 保持为空，继续走 legacy recovery 语义。

回退 v0.4.3 前必须停止 v0.4.4 Worker 并恢复升级前 Worker data-dir 备份；不要手工降低 `PRAGMA user_version`。

## 7. Boundary

v0.4.4 不提供生产 container/VM/external sandbox implementation。它稳定的是 Provider lifecycle、durable reference、cleanup proof 与 Worker recovery contract。
