## 1. Goal

本轮分成两个发布层级：

~~~text
v0.2.0
   ↓
v0.2.1
Production Baseline
真实环境做实
   ↓
v0.3.0
Reliability Kernel I
Stage + multi-Attempt + Fencing
~~~

原则：

1. v0.2.1 不增加新的领域模型，只补真实环境证据；
2. v0.3.0 不实现自动 Retry，只先允许安全存在多代 Attempt；
3. v0.3.0 不同时扩 Runtime / Tool / Environment / Scheduler 大能力；
4. 所有 stale generation 写入必须被隔离；
5. v0.2 single / MapReduce / MCP / G1 必须保持回归通过。

### 2.2 对 v0.3.0 最关键的当前代码事实

当前 attempts 表：

~~~text
id PRIMARY KEY
task UNIQUE
generation
worker
epoch
lease_until
released
~~~

因此虽然已经存在 generation，但 task UNIQUE 导致一个 Task 只能保留一个 Attempt。

当前 assignment 仍固定：

~~~text
Generation = 1
~~~

当前 checkAttempt() 已校验：worker、generation、lease token。说明 fencing 基础已经存在，但还没有校验“是否为 Task 当前 generation”。

当前 Stage 语义存在于：

~~~text
tasks.stage = single / map / reduce
~~~

且 jobs.go 仍直接处理 MAPPING / REDUCING 和 stage == map/reduce。因此 v0.3.0 是“把已有隐式模型正式化”，不是从零重写。

## 5. M1 — Schema v4：Stage + multi-Attempt

Issue：[#2](https://github.com/tommyxie2026-tech/computecloud/issues/2)

### 5.1 主要文件

预计至少涉及：

~~~text
internal/store/db.go
internal/store/migrations.go
internal/store/migrations_test.go
internal/server/jobs.go
internal/server/tasks.go
api/agent/v1/runtime.proto（仅在确有协议字段需要时）
~~~

### 5.2 Stage 数据模型

建议最小 stages：id、job_id、kind、ordinal、state、created、updated。

v0.2 兼容映射：

~~~text
single -> Stage(kind=single)
map_reduce -> Stage(kind=map) -> Stage(kind=reduce)
~~~

Task 逐步从 stage TEXT 迁移到 stage_id。

### 5.3 Attempt 数据模型

当前 UNIQUE(task)，目标 UNIQUE(task,generation)。Task 增加等价于 current_attempt_id / current_generation 的当前所有权锚点。

必须保证：

~~~text
one Task
many historical Attempts
one active current Attempt
~~~

### 5.4 Migration Gate

- v3 -> v4 一次事务完成；
- foreign key check；
- migration fault rollback；
- active Attempt 升级边界明确；
- v0.2 single / map / reduce 历史数据可读取；
- 新数据库不能被旧二进制静默打开。

## 6. M2 — Attempt Generation

Issue：[#3](https://github.com/tommyxie2026-tech/computecloud/issues/3)

当前 assignment 固定 Generation=1，必须改为 Task 事务性 generation。

创建 Attempt 时：

~~~text
read current_generation
        ↓
next_generation = current + 1
        ↓
insert Attempt(task, generation)
        ↓
bind Task.current_attempt/current_generation
        ↓
save start command
~~~

上述过程必须处于同一事务边界。

不变量：

- (task,generation) 唯一；
- 一个 Task 最多一个 active Attempt；
- released Attempt 永不重新成为 current；
- Server restart 后可恢复 current Attempt；
- Worker reconnect 不改变 generation ownership。

## 7. M3 — Generation Fencing

Issue：[#4](https://github.com/tommyxie2026-tech/computecloud/issues/4)

Worker 任何状态写入必须通过 attempt_id + generation + worker_id + worker_epoch + lease token + Task.current_generation 校验。

当前 checkAttempt() 已校验大部分 Attempt 身份，v0.3.0 重点补：attempt.generation == task.current_generation 且 attempt.id == task.current_attempt。

覆盖：lease renew、ReportEvents、UploadArtifact、CompleteAttempt、command ACK、stop/reconcile、reconnect/replay。

stale 行为：heartbeat 不续租；event 拒绝；completion 拒绝；artifact 拒绝或 ORPHANED；command ACK 不转移状态所有权。

## 8. M4 — Stage Controller

Issue：[#5](https://github.com/tommyxie2026-tech/computecloud/issues/5)

目标：减少 jobs.go 对 MAPPING / REDUCING / stage==map / stage==reduce 的业务硬编码。

v0.3.0 只支持 single、map、reduce、barrier，为未来 fan-out/fan-in 保留模型，但不开放任意 Stage DSL。

下一 Stage 创建必须原子、幂等；Server crash 前后不能重复；输入 Artifact 集合冻结；重启后得到同一个逻辑 Stage/Task 集合。

## 9. M5 — Artifact Generation Gating

Issue：[#6](https://github.com/tommyxie2026-tech/computecloud/issues/6)

v0.3.0 只实现可靠性需要的最低状态：STAGED / ACCEPTED / ORPHANED。

最小字段：artifact_id、task_id、attempt_id、generation、kind、checksum、size、state。

只有 artifact.generation == task.current_generation、Attempt 为 current accepted Attempt、Artifact.state == ACCEPTED 时，才能进入 Reduce manifest、Job Result 和正式下载路径。

## 10. M6 — Fault / Race / Migration Matrix

Issue：[#7](https://github.com/tommyxie2026-tech/computecloud/issues/7)

| Case | 预期 |
| --- | --- |
| old Worker after generation+1 | 无有效写入 |
| stale renew | 无新 lease |
| stale event | rejected |
| stale artifact | rejected/ORPHANED |
| stale complete | rejected |
| old/new complete race | 仅 current generation 接受 |
| cancel vs complete | 事务顺序确定 |
| timeout vs complete | 事务顺序确定 |
| Server crash during bind | 无双 active Attempt |
| Server crash around barrier | 无重复下一 Stage |
| old worker epoch reconnect | 不恢复所有权 |
| schema v3->v4 | 成功迁移 |
| migration injected failure | 原库不损坏 |
| v0.2 single | regression pass |
| v0.2 MapReduce | regression pass |
| MCP | regression pass |
| G1 | regression pass |
| SQLite busy/full | 状态不损坏 |

Release invariants：

~~~text
0 duplicate accepted executions
0 stale-generation accepted writes
0 invalid artifact publication
0 duplicated next Stage
~~~
