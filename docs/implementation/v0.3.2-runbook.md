# v0.3.2 Artifact Lifecycle 运行与升级

- 目标版本：v0.3.2
- Server schema：v6
- 基线：v0.3.1 / schema v5
- ADR：[ADR-007](../adr/0007-artifact-lifecycle.md)

## 1. 状态说明

~~~text
STAGED -> ACCEPTED
STAGED -> ORPHANED -> DELETING -> DELETED
~~~

ACCEPTED 是唯一对用户和下游 Stage 有效的 Artifact；ORPHANED 保留固定安全窗口；DELETING 是可重放删除事务的持久状态；DELETED 是 tombstone，不再关联文件路径。

## 2. Reference

查看引用：

~~~sql
SELECT artifact, ref_type, ref_id, created
FROM artifact_refs
ORDER BY artifact, ref_type, ref_id;
~~~

当前 reference 类型为 `task_result`、`reduce_input`、`job_result`。被 reference 的 ACCEPTED Artifact 不会被自动 GC。

## 3. 升级 v0.3.1 -> v0.3.2

沿用现有 Server migration drain gate：停止新 Job；等待 active Attempt 归零；停 Server；离线备份 data directory；部署 v0.3.2；启动并检查 schema。

检查：

~~~sql
PRAGMA user_version;
PRAGMA integrity_check;
PRAGMA foreign_key_check;
~~~

预期 `user_version = 6`、`integrity_check = ok`、`foreign_key_check` 无记录。

Migration 会重建 artifacts 表并增加 lifecycle 字段；把现有 ACCEPTED Artifact 固化为 task_result ref；给已有 ORPHANED Artifact 设置安全 GC 时间；建立 lifecycle/ref triggers。Migration 事务不会删除 Artifact 文件。

## 4. Lifecycle inspection

~~~sql
SELECT state, count(*), coalesce(sum(size),0)
FROM artifacts
GROUP BY state
ORDER BY state;

SELECT id, task, attempt, generation, gc_after
FROM artifacts
WHERE state='ORPHANED'
ORDER BY gc_after, id;

SELECT id, path, updated
FROM artifacts
WHERE state='DELETING';
~~~

## 5. Reconciliation

~~~text
ORPHANED + no ref + gc_after expired
    ↓
DELETING
    ↓
unlink local file
    ↓
DELETED + path='' + deleted_at
~~~

如果 Server 在 DELETING 后崩溃，重启后继续执行；文件已经不存在不是错误。不要手工把 ACCEPTED Artifact 改成 ORPHANED/DELETING，schema trigger 会拒绝有 reference 的对象。

## 6. Filesystem residue

Server 仅自动处理老化的 `.upload-*`，以及老化且 DB 无 metadata 的合法 Artifact-ID 文件。不要把 Artifact 目录当作 source of truth；DB metadata + reference 才是有效性依据。

## 7. 回退

v0.3.1 binary 不应直接打开 schema v6。回退时停止 v0.3.2，保存现场副本，恢复升级前 v0.3.1 backup，使用 v0.3.1 binary 启动并执行 integrity/smoke/task-flow 检查。不要手工把 `PRAGMA user_version` 从 6 改回 5。

## 8. 告警建议

至少巡检 DELETING 长时间不归零、ORPHANED 数量/字节持续增长、Artifact 目录与 DB 记录明显偏离、`ARTIFACT_MISSING`、`ARTIFACT_CORRUPT`、SQLite integrity/foreign key error。

## 9. 边界

24h orphan grace 是实现安全窗口，不是 retention SLA。v0.3.2 不负责用户 TTL、全历史数据清理、Workspace GC、远端对象存储、跨节点 shared storage 或 tombstone 最终清除。
