# v0.4.6 Ubuntu Server + MacBook Air Worker 容器化验证

本文用于验证 v0.4.6 正式容器：远程 Ubuntu 运行 Server，MacBook Air 通过 Docker Desktop 运行 Linux Worker。首次验证使用新的数据目录，不复用旧的 0.3.2 原生部署数据。

## 固定产物

使用正式发布 digest，不使用 `latest`：

```text
Server: ghcr.io/tommyxie2026-tech/computecloud-server@sha256:5a6bd63e2e255c593c7e848ba59c19220fadd2ddab3f74983e9bd4d684313d5b
Worker: ghcr.io/tommyxie2026-tech/computecloud-worker@sha256:424378982d61b31d7cb69cd8026ffb258663d239ee7511e3453d59960e905c9a
```

Apple Silicon Mac 使用 `linux/arm64` Worker；Intel Mac 使用 `linux/amd64`。Server 镜像按 Ubuntu 主机架构选择。

## 目录和权限

Ubuntu：

```text
${SERVER_ROOT}/{config, data/server, secrets, logs}
```

MacBook Air：

```text
${WORKER_ROOT}/{config, data/worker-air, secrets, repos, logs}
```

Server 数据目录和 Worker 数据目录必须独立。Server 私钥只挂载到 Server；Worker 和客户端只挂载 CA。容器默认以 UID/GID `65532` 运行，数据目录需允许该用户写入。

## 网络和 TLS

- Ubuntu `7443/tcp`：Worker gRPC over TLS。
- Ubuntu `7444/tcp`：Job/Control HTTPS。
- 证书 SAN 必须包含 MacBook Air 实际访问的 Ubuntu IP 或 DNS。
- 防火墙只允许 Worker 网段访问 7443，只允许受信客户端访问 7444。
- 跨主机连接禁止使用 `insecure_loopback` 或明文 HTTP。

验证证书：

```sh
openssl x509 -in secrets/server.crt -text -noout | grep -A1 'Subject Alternative Name'
openssl s_client -connect <UBUNTU_IP>:7443 -CAfile secrets/ca.crt -verify_return_error </dev/null
```

## Ubuntu Server

拉取并检查镜像：

```sh
docker pull ghcr.io/tommyxie2026-tech/computecloud-server@sha256:5a6bd63e2e255c593c7e848ba59c19220fadd2ddab3f74983e9bd4d684313d5b
docker image inspect ghcr.io/tommyxie2026-tech/computecloud-server@sha256:5a6bd63e2e255c593c7e848ba59c19220fadd2ddab3f74983e9bd4d684313d5b
```

`config/server.yaml` 至少包含：

```yaml
server:
  listen: 0.0.0.0:7443
  data_dir: /var/lib/computecloud
  http:
    listen: 0.0.0.0:7444
    allowed_origins: []
  tls:
    cert_file: /run/secrets/server.crt
    key_file: /run/secrets/server.key
```

补充 `worker-air` 的唯一 ID、节点 Token、项目授权和 Job 配置；Token 不写入 YAML 明文。

启动：

```sh
docker run -d --name computecloud-v046-server --restart unless-stopped \
  --user 65532:65532 -p 7443:7443 -p 7444:7444 \
  -v "$PWD/config/server.yaml:/etc/computecloud/computecloud.yaml:ro" \
  -v "$PWD/data/server:/var/lib/computecloud" \
  -v "$PWD/secrets/server.crt:/run/secrets/server.crt:ro" \
  -v "$PWD/secrets/server.key:/run/secrets/server.key:ro" \
  -v "$PWD/secrets/worker-air.token:/run/secrets/worker-air.token:ro" \
  ghcr.io/tommyxie2026-tech/computecloud-server@sha256:5a6bd63e2e255c593c7e848ba59c19220fadd2ddab3f74983e9bd4d684313d5b
```

检查：

```sh
docker logs --tail=200 computecloud-v046-server
curl --fail --cacert secrets/ca.crt \
  -H "Authorization: Bearer $(cat secrets/operator.token)" \
  https://<UBUNTU_IP>:7444/v1/capabilities
sqlite3 -readonly data/server/state.db \
  'PRAGMA user_version; PRAGMA integrity_check; PRAGMA foreign_key_check;'
```

v0.4.6 预期 Server schema 为 v13，`integrity_check` 为 `ok`，`foreign_key_check` 无输出。

## MacBook Air Worker

先确认 Docker Desktop 架构：

```sh
docker info --format '{{.Architecture}}'
```

拉取 Worker：

```sh
docker pull ghcr.io/tommyxie2026-tech/computecloud-worker@sha256:424378982d61b31d7cb69cd8026ffb258663d239ee7511e3453d59960e905c9a
```

`config/worker-air.yaml` 使用容器路径：

```yaml
worker:
  id: worker-air
  server_address: <UBUNTU_IP_OR_DNS>:7443
  data_dir: /var/lib/computecloud
  token_file: /run/secrets/worker-air.token
  tls:
    ca_file: /run/secrets/ca.crt
  repositories:
    demo-repo: /repos/demo
```

启动：

```sh
docker run -d --name computecloud-v046-worker-air --restart unless-stopped \
  --user 65532:65532 \
  -v "$PWD/config/worker-air.yaml:/etc/computecloud/computecloud.yaml:ro" \
  -v "$PWD/data/worker-air:/var/lib/computecloud" \
  -v "$PWD/secrets/ca.crt:/run/secrets/ca.crt:ro" \
  -v "$PWD/secrets/worker-air.token:/run/secrets/worker-air.token:ro" \
  -v "$PWD/repos:/repos:ro" \
  ghcr.io/tommyxie2026-tech/computecloud-worker@sha256:424378982d61b31d7cb69cd8026ffb258663d239ee7511e3453d59960e905c9a
```

确认 Worker 注册、epoch、slots 和 capability：

```sh
docker logs --tail=200 computecloud-v046-worker-air
computecloud workers --config client.yaml
```

基础 Worker 镜像不包含 Codex/Claude CLI。真实 CLI 验证需要另外构建并固定版本的派生镜像。

## 验证顺序

1. TLS 链、证书 SAN、Token、权限和日志脱敏。
2. Worker 注册和 Server/Worker 版本检查。
3. single Job：提交、查询、事件、结果和 Artifact SHA-256。
4. 相同幂等键重试；相同键不同请求体必须拒绝。
5. Map/Reduce 或双分片任务，确认 Worker 能执行并清理 workspace。
6. 运行中取消，确认执行环境停止后才进入最终状态。
7. 重启 Server、重启 Worker、强制停止 Worker，确认不重复创建 Attempt。
8. 断开 Worker 网络，验证租约、核查和恢复行为。
9. 运行 `make capacity-check`，再用固定资源重复容量矩阵至少三次。

确定性门禁：

```sh
make smoke
make ci-flow
make ci-retry-flow
make ci-artifact-flow
make ci-workspace-flow
make ci-agent-control-fencing
make ci-agent-control-negative
make ci-manual-retry-negative
```

每次测试保存 Job/Task/Attempt ID、容器 ID、镜像 digest、日志、事件水位、Artifact hash、故障注入时间和恢复时间。fixture 结果不能代替真实 Codex/Claude 生产验收。

## 升级和回滚

首次验证使用新数据卷。已有部署升级前必须停止新提交、排空或取消活动 Attempt、停止所有旧容器，并备份完整 Server/Worker data directory。启动顺序为 Server → 检查 schema 和完整性 → Worker → 受控任务验证。

旧版本不得打开已升级数据库；禁止手工修改 `PRAGMA user_version`。如果数据目录来自更高 schema 的开发分支，不能直接用 v0.4.6 回退，必须使用兼容备份或新的隔离数据卷。
