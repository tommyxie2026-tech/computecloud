# v0.4.7 Stable Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the remaining v0.4.x implementation and real-environment gates, then publish `v0.4.7` as the next stable Agent-aware Distributed Job Execution Platform / Agent Job Executor release.

**Architecture:** Keep Server as the only Job/Task/Attempt/Artifact truth and keep `direct` as the default transport. Finish the experimental Relay foundation without inspecting inner TLS payloads, collect real-environment evidence through versioned JSON reports, and let one deterministic release-gate validator decide whether the stable release request may be created.

**Tech Stack:** Go 1.27.1, gRPC/HTTP2, SQLite, Python 3 validation tooling, Docker/OCI, GitHub Actions.

**Spec:** `docs/implementation/v0.4-closeout-plan.md`

## Global Constraints

- Product scope remains Agent-aware Distributed Job Execution Platform / Agent Job Executor.
- Do not add an AI Execution OS, generic Workflow Engine, LLM Gateway, Model Serving Platform, or GPU Cloud.
- `direct` remains the default; `direct_then_relay` remains explicit opt-in.
- Relay stays opaque to inner TLS and never becomes a Job/Task/Attempt/Artifact fact source.
- Automatic Goal Re-plan remains disabled for v0.4.7.
- Claude token limits, Codex token/cost limits, and mixed-provider finite budgets remain fail closed.
- Fixture/CI evidence cannot satisfy a real-host acceptance case.
- Stable release requires the exact candidate SHA, no open critical correctness failure, full CI, upgrade/restore evidence, and all required tracker rows `DONE`.

## Review Focus

- A saturated Artifact/Bulk transfer must not prevent lease, cancel, or control traffic from completing within the bounded test deadline; Task 1 owns this test.
- Relay metric collection must stay bounded and must never include tickets, bearer tokens, prompts, Artifact contents, or Worker payloads; Task 2 owns this test.
- A real-environment report with duplicate hosts, mismatched source SHAs, missing native finals, or fixture model calls must fail closed; Tasks 3 and 6 own these tests.
- Upgrade evidence must prove restoration from the v13 snapshot rather than a manual schema downgrade; Task 6 owns this validation.
- A release request must be rejected when any required case is `FAILED`, `BLOCKED_ENV`, `NOT_RUN`, or absent; Task 7 owns this test.
