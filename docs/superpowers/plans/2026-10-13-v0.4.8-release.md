# v0.4.8 CI 发布计划

**目标：** 从已通过 main CI 的公网访问安全加固提交生成 v0.4.8 Linux 二进制和多架构 Server/Worker OCI 镜像，并由 GitHub Actions 创建正式 Release。

**方式：** 在 `main` 上将 `Makefile` 版本提升到 `0.4.8`，增加工作流识别的 `release/v0.4.8.json` 请求。PR CI 先验证候选；合入后 main push 的 package、container-publish 和 release job 按仓库现有流程生成正式产物。

**约束：** 不覆盖已存在的 v0.4.7 tag；不将 CI 结果表述为目标公网生产环境认证；Release 说明保留未完成安全验收的限制。

## 步骤

1. 更新版本号、发布请求和中文变更记录；核对请求 schema 与 Makefile 版本一致。
2. 运行本地发布契约测试，提交并推送发布 PR。
3. 等待 PR CI 全部必需检查通过，再按用户授权合入。
4. 检查合入 SHA 的 CI package、双架构容器发布和 GitHub Release；读取 Release 资产与 Server/Worker digest。
5. 仅在发布确认后补写 README 和 v0.4.8 发布记录，准确记录实际 SHA、CI 与 digest。

## 验收

- Release tag `v0.4.8` 只创建一次，目标为含发布请求的合入 commit。
- CI package 与 Server/Worker `linux/amd64`、`linux/arm64` 镜像发布成功。
- Release 附带 `SHA256SUMS` 与 `CONTAINER_IMAGES.txt`，记录的 digest 可从 GHCR 查询。
- 发布记录明确区分 CI 发布成功与公网不可信租户验收未完成。
