# v0.4.9 稳定收尾迭代计划

> **For agentic workers:** 实施前使用 `superpowers:executing-plans`，逐任务完成并验证。每项使用 checkbox 跟踪。

**目标：** 在 v0.4.8 稳定版之后，以最小范围交付主线已合入的长请求处理、Worker 部署加固和 Claude Attempt Gateway，并修正文档状态，形成可审计的 v0.4.9 候选发布。

**架构：** 保持现有 Server/Worker、durable Job/Task/Attempt 和 SQLite 执行事实源。该迭代主要冻结和验证已合入能力，不扩大为通用 LLM Gateway、AI Execution OS 或通用 Workflow Engine；真实主机验收单独跟踪，不从 CI 推定通过。

**技术栈：** Go、现有 Go 测试与 CI Gate、Python 验收脚本、多架构 OCI 构建和 GitHub Release 流程。

**规格来源：** `README.md`、`docs/implementation/v0.4.8-release-status.md`、`docs/implementation/v0.4-closeout-plan.md`、`docs/implementation/p0-p2-execution.md`、`docs/implementation/long-term-roadmap.md`、`docs/implementation/public-access-security-tracker.md`、`docs/superpowers/specs/claude-attempt-gateway-design.md`、`docs/superpowers/specs/worker-deployment-hardening-design.md`。

## 全局约束

- 产品定位保持 Agent-aware Distributed Job Execution Platform / Agent Job Executor。
- 当前稳定基线为 v0.4.8；Server schema v19、Worker schema v6，以主线 README 和迁移测试为准。
- PR #148 与 PR #150 已进入 main；v0.4.9 计划不得将它们误记为未合并功能。
- 真实 Runtime、隔离负向测试、证书轮换/撤销、双机恢复、供应商账单硬上限仍是独立目标环境验收项；此前确认的 CI 发版门禁不因此改变。
- 不把真实域名、主机名、IP、个人路径、任务 ID、提示词、用量或密钥写入项目文档、测试输出或发布记录。
- 不提交本机部署验证指南、环境安全报告或本机部署检查脚本。
- v0.5.0 的 Agent-aware Scheduler、Mobile pairing/push 和 Execution Usage MVP 不纳入本次发布范围。

## 复核重点

- Gateway 上游返回未知/缺失 usage：保持 Attempt 后续调用 fail-closed，不能以零用量结算。
- SSE 未收到完整终止事件或上游中断：不能提前成功结算或丢失不确定状态。
- 不受支持的 Beta/header、query、重定向或模型：在访问上游前拒绝。
- Attempt Token、长期上游 Key、提示词和响应正文：不得进入普通日志、持久化记录或 Artifact。
- strict OCI/Worker 配置发生网络、环境变量或容器参数偏移：调度或启动必须拒绝，不可静默退回宽松模式。

## v0.4.9 不纳入范围

- 真实双机/真实 Provider/24 小时任务、真实 NAT Relay、WAF/源站配置、证书轮换撤销、OCI escape、真实 egress 防火墙与供应商账单硬上限；它们按目标环境验收继续跟踪，不从 CI 推断结果。
- Agent-aware Scheduler 的新评分策略；该能力进入 v0.5.0 规格，延续“确定性软评分、默认关闭”决策。
- Mobile pairing/push/signing、Execution Usage MVP、Artifact Storage Provider 与多 Worker 容量扩展；需各自独立切片与验收 Gate。
